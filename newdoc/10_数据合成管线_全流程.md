## 2 分阶段说明

### 2.1 D0 静态库（`new_demo/data_static/`）

```text
职责      只存库文件与提示词；不抽样、不调模型、不编号

库文件
  D0_homes.jsonl      15 套户型，只有房间（room_id / display_name / room_kind），不挂设备
  D0_devices.jsonl    21 条设备/传感器能力（kind、device_type、state、actions、allowed_room_kinds），不绑房间
  D0_personas.jsonl   25 条画像，只影响 intent 口吻，不进 C/D4/D6 判定

提示词模板（19 份）
  T1..T5_*.md           5 份  D2-1 写 task     占位符 {{s0}}、{{persona}}
  D0_request_T1..T5.md  5 份  D2-2 写用户话     占位符 {{intent}}、{{task}}、{{display_names}}
  D3_review_T1..T5.md   5 份  D3 审话          占位符 {{rooms}}、{{display_names}}、{{intent}}、{{task}}、{{user_request}}
  D6_T3/T4/T5.md        3 份  D6 裁判          占位符 {{category}}、{{user_request}}、{{finish}}、{{turns}}
  A_policy.md           1 份  A 的 system      占位符 {{tools}}
```

### 2.2 D1 HomeMaker（`data/D1_home_maker.py`）

```text
职责      seed -> s0；不用模型，不读画像
输入      1) D0_homes.jsonl  2) D0_devices.jsonl  3) seed
输出      s0 = {rooms:[{room_id,display_name,device_ids}], devices:[{device_id,room_id,display_name,
             kind,device_type,state,actions,available}]}

抽样规则
  按户型大小：small 每房 1–2 台、全屋 5；medium 每房 2–3、全屋 10；large 每房 2–3、全屋 14
  必挂顺序：空调 -> 传感器 -> 可调光灯（主灯或台灯）-> 另一盏灯（优先空房间）-> 保证灯 >= 2
           -> 冰箱 -> 烤箱 -> 洗碗机 -> 热水器 -> 洗衣机（先卫生间后阳台）-> 电视 -> 加湿器
  全屋唯一：tv / water_heater / washer / dishwasher / oven / refrigerator / humidifier
  同房不重复 catalog_id；房间不允许就不挂

命名与 id
  device_id      sensor_{房间token}_{id_token} 或 device_{房间token}_{id_token}
  display_name   房间中文名 + name_stem（例：卧室主灯、厨房冰箱）

初始 state
  on 随机 true/false；mode 取该设备 enum；target 按该设备 set_temperature 的 min/max/step 取点；
  level 按 set_percentage 的 min/max/step 取点；传感器温度 16–32、湿度 30–80
  seed 不写进 s0
```

### 2.3 D2-1 写 task（`data/D2_task_writer.py`，外部 DeepSeek）

```text
输入      s0、persona、category（T1..T5）
提示词    由 D0_template.build_prompt("task", T, {"s0":…, "persona":…}) 装配
输出      {task, probe, request_id} 或 {error_code:"INVALID_TASK_JSON", error_message}

形状校验（不通过就不写用户话）
  必备键            intent / conditions / keep / required_observations / expected_finish
  intent            非空字符串
  outcome           只许 completed / refused；禁止 facts 和 answered
  T1/T2/T3/T5       outcome=completed；conditions 的 operator 只许 eq/ge/le；keep 只许 eq
  T1/T2/T3/T5       required_observations 必须为空数组
  T4                outcome=refused；conditions 为空；required_observations 非空；probe 必填
  ge/le 的 value    必须等于 s0 里该字段当前值（doc/29）
  T3 already holds  eq 已成立 -> 废题；ge 顶到 max、le 顶到 min -> 废题；不再拿旧门槛判废
```

### 2.4 D2-2 写用户话（`data/D2_request_writer.py`，外部 DeepSeek）

```text
输入      task（含 intent）、s0 的 display_names、该类 request 模板
规则      eq 说精确（点名设备 + 目标），ge/le 只说方向不报数字；
          T2 按 condition 逐条拼成一句；T4 把非法数值说成普通精确指令
输出      一句中文 user_request；去围栏、去首尾引号、去换行
失败      INVALID_REQUEST_TEXT（空文本）
```

### 2.5 D3 审用户话（`data/D3_reviewer.py`，先程序后模型）

```text
第一步：程序硬泄露扫描（不调模型）
  命中即 HARD_LEAKAGE：
    动作名 turn_on / turn_off / toggle / set_mode / set_temperature / set_percentage
    工具名 observe_home / inspect_room / inspect_device / execute_action
    reason_code、OUT_OF_SAFE_RANGE、READ_ONLY_DEVICE、device_id、room_id
    task 里出现过的任何 device_id / room_id 原文
    形如 {"name":…} / {"arguments":…} / {"device_id":…} 的 JSON 碎片

第二步：模型审查（external）
  输入 intent / task / user_request / 房间名 / 设备名
  输出 {"accept": true/false, "codes": [...]}
  codes 只收 TARGET_NOT_COVERED / EXTRA_INTENT / HARD_LEAKAGE
  accept 与 codes 冲突时按拒绝处理；拒了却没给码记 TARGET_NOT_COVERED
不通过 -> D34_failures.jsonl，不发 blueprint_id
```

### 2.6 D4 Oracle 验可行性（`data/D4_oracle.py`，不调模型）

```text
职责      复制 s0 打 B，只看 ok / error.code；不看终态是否满足（那是 C-2）
静态检查  conditions / keep / required_observations / probe 的 device_id 必须在 s0

按类执行
  T1/T2/T3（completed + conditions）
      eq   -> 按 field 映射动作写一次：on->turn_on/off、mode->set_mode、target->set_temperature、
             level->set_percentage；值用 condition.value
      ge/le-> 只能 target/level；沿方向挪一档（step 来自该设备 actions，缺省 target 0.5、level 1.0）；
             顶到 min/max 挪不动 -> BAD_REQUEST，蓝图不合格
      任何一次失败 -> 整张草案不合格
  T4（refused + probe）
      probe 必须是 s0 里真实动作；打出去必须失败，且副本 state 与 s0 完全一致，否则不合格
  T5（completed，conditions 空）
      只做静态检查；没有必须观察的项，通过

输出      通过：blueprint_id + category + home + task + user_request（probe 不写入）
          不通过：{stage:"D4", error_code, message}，无 id
```

### 2.7 停闸（`PIPE_pipeline._persist_d4`）

```text
写出     D4_blueprints.jsonl（过审，带 bp_*）
         D34_failures.jsonl（D2/D3/D4 失败，无 id）
         D2_drafts.jsonl（所有草稿）
         reports/D4_preview.md（给人看：每条的类别、用户话、设备、intent + 失败清单）
删除     D5_trajectories.jsonl（如果存在）
规则     确认前不跑 D5；--full 才跳过等人
```

### 2.8 D5 开跑（`data/D5_run.py` + `eval/C_episode_runner.py`）

```text
蓝图 -> Scenario 六项：
  scenario_id / blueprint_id / home / user_request / task / episode_config
  episode_config 固定 {"max_turns": 10, "max_tool_calls_per_turn": 1}

C.run 每轮：
  context = observation + tools + history + protocol_feedback + turn_index + max_turns
  A.respond(context) -> 一个工具或 finish
  两个工具 -> TOO_MANY_TOOL_CALLS，本轮不执行；解析失败 -> INVALID_ASSISTANT_RESPONSE，消耗一轮
  家庭工具 -> B.step；finish 由 C 自己收下，不传 B
  工具报错 -> 下一轮以 protocol_feedback 形式回给 A

输出行（写 D5_trajectories.jsonl）
  {scenario, record, labels(C-1..C-4), category, d6(跳过/待审), d6_votes}
  record 五项：scenario_id / turns / final_state / finish / protocol
```

### 2.9 D6 复核（`data/D6_judge.py`，external 三票）

```text
门槛      C-1..C-4 全 true 且 category 属 T3/T4/T5 且 d6=待审；T1/T2 直接「跳过」
问法      T3 是否落实唯一隐藏目标；T4 拒绝说明是否贴着 inspect 范围；T5 summary 是否答对问题
票制      独立问三次，每次只输出 对 / 错；2 票及以上「对」记「对」，否则「错」
兜底      有效票不足 3 张 -> system_failure（待重跑）；解析失败不记成「错」
```

### 2.10 进数据集（`data/D_copy_dataset.py`）

```text
复制条件  C-1..C-4 全 true 且 d6 ∈ {对, 跳过}
落盘      data_processed/D_dataset.jsonl + D_manifest.json
总表      D5_trajectories.jsonl 一条不删，失败留在总表
```

## 3 两种跑法

```text
分段跑（默认，人工停闸）
  python -m new_demo.PIPE_run --per-category 5 --seed 20260928 --workers 10
      -> D1..D4，写蓝图与失败，停下
  人工看 reports/D4_preview.md
  python -m new_demo.PIPE_run --continue-from-d5 --workers 5
      -> D5 + D6 + 复制数据集

一次到底
  python -m new_demo.PIPE_run --full --per-category 2

配额跑（每类凑满成功条数）
  python -m new_demo.PIPE_run --quota --target-success 50 --max-attempts 100 --workers-per-category 10
      -> 每条样本从 D1 一路跑到 D6，成功满额即停；失败继续补，直到 max_attempts

CLI 参数
  --output-dir            产物根目录；默认 new_demo/ 自身，批次跑指向 new_demo/runs/<批次>
  --per-category          每类草稿数（非配额模式）
  --seed                  规划种子；主线程先排好 类别/portrait/home_seed，再并发
  --categories            逗号分隔，如 T1,T2；空则五类
  --workers               D2–D4 与 D5–D6 两段的并发条数
  --quota                 配额模式
  --target-success        配额模式每类成功目标，默认 50
  --max-attempts          配额模式每类最多尝试，默认 100
  --workers-per-category  配额模式每类并发，默认 10
  --continue-from-d5      只跑后半段
  --full                  D4 后不停闸
```

## 5 标签口径

```text
C-1 协议     finish_requested 且未 truncated 且没有 TOO_MANY_TOOL_CALLS
C-2 终态     conditions 全过且 keep 全过（空数组过）
             eq：终态 == value；ge/le：终态比 s0 初值严格更高/更低
C-3 观察     required_observations 都有成功 inspect（空数组过；实际只有 T4 非空）
C-4 finish   outcome 与 expected_finish 对齐；refused 的 reason_code 必须在允许集合；
             有 facts -> 失败；completed 带 reason_code -> 失败

进集 = C-1..C-4 全 true 且（T1/T2 的 d6=跳过 或 T3/T4/T5 的 d6=对）
```
