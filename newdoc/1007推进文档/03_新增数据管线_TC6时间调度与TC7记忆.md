# 03 新增两条数据管线：TC6 时间调度与 TC7 记忆

> 依据：`1004推进文档/01_数据合成管线`、`1004推进文档/02_模块功能与输入输出示例`、`01_下一版方案总体讨论`、`02_时间机制方案对比`、
> 现有 `new_demo/` 代码（D0~D6 与 ABCD）。
> 目标：在 T1~T5 老管线不动的前提下，新增两条可独立跑、可独立评测的数据管线。
> 本文只定类别、路径、模块职责、提示词规格与评测口径，不写实现代码。

## 0 一屏

```text
新增两条管线，五个子类：

TC6 时间调度（一次性，不做持久规则）
  TC6A 绝对时间     "今晚 10 点把客厅灯关掉"
  TC6B 相对时间     "40 分钟后把加湿器关掉"

TC7 记忆（记忆内容为整段文本）
  TC7A 读预置记忆   "把卧室空气弄舒服点"（记忆里已写"对花粉过敏，别开窗"）
  TC7B 单轮读写     "记住：睡觉要关客厅灯；顺便把卧室灯调暗一点"
  TC7C 多轮不 reset 第1轮写记忆，第2轮用记忆，第3轮查状态（同一会话）

与老管线的关系：
  老管线 T1~T5 一行不改、一条数据不重跑；
  新管线走新目录、新模板、新账本、新评测集；
  TC6 / TC7 的模型侧下发全部 8 个工具（observe_home / inspect_room /
  inspect_device / execute_action / finish / inspect_time / time_control / memory）；
  T1~T5 的工具面保持现状不动；
  B/C 只做"可选参数"级别的扩展（reset 多收一个 tc 块），老调用不受影响。

设备变更：
  新增空气净化器（air_purifier）：只有 turn_on / turn_off 两个动作，
  没有 mode / level / target；TC6 / TC7 场景都可以用
  （例如"花粉过敏 → 开净化器"）；老设备集与老数据保持不动。
```

## 1 五个子类的定义与成功标准

### 1.1 TC6A 绝对时间

```text
例子      now=2026-10-09 09:30，用户："今晚 10 点把客厅灯关掉"
期望轨迹  inspect_time → 算出 at=2026-10-09 22:00 → schedule(steps=[客厅灯 turn_off]) → finish
成功标准  ① 下单：at 与期望一致（分钟级）、模型 steps 与 due_steps 一致、单建立
          ② 结算：影子执行后客厅灯 on=false（到点掉线本期不处理）
边界      过去时间 / 超 7 天 / "今晚"已过 / "每晚"（持久规则，本版不做）
```

### 1.2 TC6B 相对时间

```text
例子      now=2026-10-09 09:30，用户："40 分钟后把加湿器关掉"
期望轨迹  inspect_time → 09:30 + 40 分钟 = 10:10 → schedule(at=10:10, steps=[加湿器 turn_off])
成功标准  同 TC6A 两段；相对时间多考一步"读时钟 + 加法"，含跨天
边界      偏移范围、跨午夜（23:40+40→次日 00:20）、"过一会儿"（模糊，不收录）
```

### 1.3 TC7A 读预置记忆（单轮）

```text
预置      记忆 = "用户对花粉过敏，不要开窗"
例子      用户："把卧室空气弄舒服点"
期望轨迹  memory.read → 不开窗，开空气净化器（或空调）→ finish
成功标准  行为符合记忆约束：该避开的动作没做，该做的动作做了
```

### 1.4 TC7B 单轮内读写记忆（单轮）

```text
例子      用户："记住：我睡觉要关客厅灯；顺便把卧室灯调暗一点"
期望轨迹  memory.write("睡觉要关客厅灯") → （回读可选）→ 执行调暗 → finish
成功标准  ① 记忆内容准确（无增删改）② 不把"要记住的事"当成现在要执行的动作
          ③ 真实动作（调暗）执行正确
```

### 1.5 TC7C 多轮不 reset（会话）

```text
会话      第1轮 "记住：我睡觉要关客厅灯"        模型：memory.write
          第2轮 "我要睡了"                      模型：memory.read → 关客厅灯
          第3轮 "客厅灯关了吗？"                模型：inspect → 如实回答
成功标准  每轮各自的成功 + 跨轮使用（第2轮真的读了第1轮写的记忆）
          + 会话卫生（会话结束记忆清空，不串到下一个任务）
```

## 3 两条管线的 ABCD 分工

```text
scenario 的新增块（可选；老管线没有这块，B 读到就跳过）：
  tc: {
    kind:            "TC6A" / "TC6B" / "TC7A" / "TC7B" / "TC7C"
                     只给 D 与 C 用；B 不按 kind 分支
    base_time:       "2026-10-09 09:30"   TC6 用，reset 时解析成 now
    horizon_minutes: 10080                TC6 用，7 天窗口
    memory_initial:  "..."                TC7 用；"开局时的记忆内容"，
                                           reset 时复制成 B 的运行时 memory（可被整段改写）
    session_turns:   3                    仅 TC7C 用
    due_state:       可选，到点状态快照     结算时用
  }

B 的 reset 签名保持 reset(scenario)，从 scenario.tc 读它需要的字段；
老管线不传这块，reset 行为与现在完全一致。

名词区分：memory_initial 是 D 写死的初始内容（持久、不会被模型改）；
memory 是 B 运行时的那份副本（会话级，模型可读可整段替换，会话结束丢弃）。
```

### 3.1 TC6 管线

```text
A 策略
  工具面    全部 8 个都下发（含 memory）；TC6 也会看到与本子类无关的工具
  提示词    新增"时间调度"一节：先 inspect_time，再算 at（绝对填时刻 / 相对做加法），再写单；
            过去时间、超 7 天、模糊相对时间的处理；finish 表示"下单完成"
  协议      不变：一次一个 JSON、等 observation、最多 12 轮
  全工具注记 模型可能调用无关工具（例如 TC6 调 memory）：判定只看任务相关行为，
            不因无关调用直接判错；但"该预约却立即执行"要单独判为时间错误

B 仿真器
  reset(scenario)：从 scenario.tc 读 base_time，初始化 now=解析后的时刻、schedules=[]；
                  memory 置空（TC6 用不到记忆，但工具可见）
  工具       inspect_time 只读；time_control 写单/查未执行单/取消
  结算       影子执行：copy 状态（可叠 due_state）→ 应用 steps → 与期望比对
  不负责     真实推进、tick、环境自主事件（本期不做）

C 回合与判定
  runner    单轮 episode，与现在相同；reset 时多传 tc
  判定      两段：① 下单（at 与期望一致、模型 steps 与 due_steps 一致、单建立）
            ② 结算（影子结果满足 conditions；掉线本期不构造、不处理）
            时间错误：不写单、直接 execute_action 把事做了，即使终态碰巧满足
            conditions，也算失败（执行时刻不对）
  指标      at 正确率、steps 与 due_steps 一致率、下单成功率、结算成功率、错误码分布

D 数据管线
  出题       TC6A/TC6B 两套 task 提示词（见第 4 节）
  审查       用户话不得出现 "YYYY-MM-DD HH:MM" 规范时刻、动作名、工具名
  Oracle     注册预约 → 影子执行 → 验证结果；过去时间/超 7 天标负例
  轨迹       turns + clock + schedules 快照 + 影子结果
```

### 3.2 TC7 管线

```text
A 策略
  工具面    全部 8 个都下发（含 inspect_time / time_control）；TC7 也会看到无关工具
  提示词    新增"记忆"一节：什么时候读（判断请求是否依赖已知偏好）、什么时候写
            （用户明确要求记住的才会写）、记忆要整段替换、写了不确认不算完成
  多轮协议  会话内每一轮仍是一次一个 JSON；每轮 finish 只结束该轮
  全工具注记 判定只看任务相关行为；但 TC7B 要求"现在就做"的动作若改成
            预约执行（time_control），算执行方式错误

B 仿真器
  reset(scenario)：从 scenario.tc 读 memory_initial 初始化 memory
                  （TC7A 有内容，TC7B / TC7C 为空）；TC7C 同时启用会话模式
  工具       memory 读整段 / 整段替换写；写超 200 token 拒绝
  会话       TC7C 一个会话 reset 一次，轮与轮之间不重置 B、不重置记忆
  清理       会话结束记忆清空（下一个任务从自己的 memory_initial 开始）

C 回合与判定
  runner    单轮（TC7A/B）与会话（TC7C）两种入口；会话轮数 2~3
  判定      TC7A：行为是否符合预置记忆（禁做项、必做项）
            TC7B：记忆内容准确 + 没把记忆当动作 + 真实动作正确
            TC7C：逐轮成功 + 第2轮是否使用第1轮的记忆 + 会话结束记忆清空
            执行方式错误：TC7B 的"现在就做"用预约代替 → 判错
  指标      记忆使用率、写入准确率、误执行率、跨轮使用率、会话污染数

D 数据管线
  出题       TC7A/TC7B/TC7C 三套 task 提示词；TC7C 的任务里要给轮次计划
  审查       用户话不得直接复述预置记忆内容（TC7A）、不得泄露后续轮要做什么
  Oracle     预置记忆 → 按记忆执行可行；写记忆 → 回读一致；会话计划可执行
  轨迹       memory 读写记录、memory_before/after、session_id、turn_index
```

## 4 D 的分情况处理（每类一套提示词）

### 4.1 出题提示词（D2-1，5 个）

```text
TC6A_task.md
  输入    s0 + persona + base_time
  输出    {子类:"TC6A", intent, time_mention, at_time_expected, due_steps[ACTION_CALL], conditions, expected_finish}
  必须写清
    at 必须是 now 之后、7 天之内、分钟级；due_steps 1~3 条且只用 s0 里真实设备
    "每晚/每天"这类持久规则出现 → 直接判废
  正例    time_mention="今晚10点", at_time_expected="2026-10-09 22:00"
  负例    at_time_expected 在过去 / 超 7 天 / 指向不存在的设备

TC6B_task.md
  输入    s0 + persona + base_time
  输出    {子类:"TC6B", intent, offset_minutes, at_time_expected, due_steps, conditions, expected_finish}
  必须写清
    offset 取 5~720 分钟；允许跨午夜；at_time_expected = base_time + offset 由数据侧算好
    "过一会儿/晚点"这类无明确数值 → 判废
  正例    offset=40, at_time_expected="2026-10-09 10:10"
  负例    23:40 + 40 分钟写成 24:20（跨天要写 次日 00:20）

TC7A_task.md
  输入    s0 + persona + base_time
  输出    {子类:"TC7A", intent, memory_initial, forbidden_actions, required_effects, expected_finish}
  必须写清
    memory_initial ≤ 200 token、与请求相关但不直接给答案（不能写"把客厅灯关掉"）
    forbidden_actions 1~2 条（例如"不许开窗"），required_effects 1~2 条
  正例    memory_initial="用户对花粉过敏，不要开窗"
  设备    可选设备包含空气净化器（air_purifier，只有开关两个动作）

TC7B_task.md
  输入    s0 + persona + base_time
  输出    {子类:"TC7B", intent, memory_expected, action_steps, conditions, expected_finish}
  必须写清
    memory_expected 一句话、可被整段替换；action_steps 与记忆内容是两件事
    请求里必须同时出现"要记住的"和"要做的"
  正例    memory_expected="睡觉时要关客厅灯"，action_steps=[卧室台灯 set_percentage 30]

TC7C_task.md
  输入    s0 + persona + base_time
  输出    {子类:"TC7C", memory_initial, turns:[{turn, goal, memory_op, action_steps, conditions}]}
  必须写清
    轮数 2~3；第 1 轮写（或读）、第 2 轮用、第 3 轮可查状态
    每轮 goal 只描述该轮，不得泄露后续轮
  正例    轮1 写"睡觉要关客厅灯"；轮2 "我要睡了"→关灯；轮3 "客厅灯关了吗"
```

### 4.2 用户话提示词（D2-2，5 个）

```text
TC6A_request.md    绝对时刻说人话："今晚10点""明天早上7点"；禁止写规范时刻
                   "2026-10-09 22:00"；禁止提设备 id/动作名
TC6B_request.md    只写偏移，不写结果时刻："40分钟后""半个小时后"；
                   禁止把算好的 10:10 说出来
TC7A_request.md    说需求，不逐条复述记忆："把卧室空气弄舒服点"；
                   禁止直接引用 memory_initial 原句
TC7B_request.md    同时给"记住"和"去做"两部分，口语自然；
                   禁止把记忆内容说成现在要执行的动作
TC7C_request.md    按轮次生成：每轮一句话；第 1 轮给要记的内容，
                   第 2 轮用自然说法触发使用（"我要睡了"），不得复述第 1 轮
```

### 4.3 审查提示词（D3）

```text
TC3_review_TC6.md
  程序段延续老 D3：动作名/工具名/device_id/HARD_LEAKAGE
  新增字面规则：出现 "YYYY-MM-DD HH:MM" 规范时刻 → HARD_LEAKAGE
  语义段：task 的 due_steps 说全没有、有没有多说设备、有没有把"今晚"说成"每晚"

TC3_review_TC7.md
  程序段：老规则 + 记忆原文是否被整句照抄（TC7A/TC7C 第2、3轮）
  语义段：请求是否依赖记忆（TC7A）、写与做是否分得清（TC7B）、
          是否泄露后续轮（TC7C）
```

### 4.4 Oracle（D4，不调模型）

```text
通用       conditions/keep/due_steps 引用的设备与字段必须在 s0 里存在
TC6A/B    写单校验（at 合法、7 天内、due_steps 设备/动作/参数合法）
          影子执行结算：验证"如果到点执行"能达成 conditions
          due_state 有值时，在快照上跑；掉线本期不处理
TC7A      用 memory_initial 推演：禁做项不执行、必做项可达成
TC7B      影子写记忆 → 回读一致 → 执行 action_steps 可达成 conditions
TC7C      逐轮推演：轮1 后记忆内容正确；轮2 在记忆存在时可执行；轮3 可读到状态
```

```text
会话新增   session_id、turn_index、每轮的 memory 快照与 finish
数据集     TC_dataset.jsonl 每条带：子类、任务字段、四段标签
          （下单/结算、记忆读/写、跨轮使用、环境故障）
```

### 4.6 语义复核（D6，仅 TC7 需要）

```text
  输入：任务记忆真值 + 轨迹 + 每轮 summary
  输出：三个二值标签——记忆读对没有、写对没有、用对没有
```

## 6 评测方案

```text
子类      主指标                                    部分分口径
TC6A/B    at 正确率；steps 与 due_steps 一致率；       at 对但 due_steps 不匹配 → 部分分；
          结算成功率；环境故障数（不构造掉线负例）      结算失败按规则记部分分
TC7A      记忆使用率（读了没有）；约束遵守率          没读记忆但行为碰巧对 → 不给使用分
          （禁做项 0 次、必做项完成）
TC7B      记忆内容准确率；误执行率；真实动作成功率   写对但动作错 / 动作对但写错 → 各记一半
TC7C      逐轮成功率；跨轮使用率；会话污染数         第2轮没读记忆但碰巧关灯 → 不给使用分

评测集构成（起步 30 条/子类，先验证管线再上量）：
  TC6A 30：同天/明天/后天、早上/晚上、过去时间负例、超 7 天负例
  TC6B 30：分钟/小时、跨午夜、接近 7 天边界、模糊表述负例
  TC7A 30：行为约束类（禁做+必做）、记忆无关时的干扰项
  TC7B 30：纯写、写+做、写错代价高的场景
  TC7C 30：2 轮/3 轮、写→用、写→用→查、会话结束清空检查

回归：新管线训练后，原 200 条 T1~T5 固定测试复测，确认老能力不退化。

全工具下发的两条硬规则（写进判定）：
  TC6：正确做法是写预约单；立即 execute_action 完成任务 = 时间错误，
       即使终态碰巧满足 conditions 也不给结算分
  TC7B：请求里"现在就做"的动作必须立即执行；改成预约执行 = 执行方式错误
```

## 7 与老管线共存的运行方式

```text
各自跑批   TC_PIPE 独立配额、独立失败重试；老 PIPE 不动
账本分开   data_processed_tc/TC_manifest.json 记子类、成功数、失败码分布
合并时机   两条管线都验证判定可靠后，再由一个 collector 把
          TC_dataset.jsonl 与 D_dataset.jsonl 合成 SFT/RL 训练集
配比       由训练侧决定（例如 T1~T5 : TC6 : TC7 = 6:2:2），
          但数据侧只提供分账本，不在管线里混
```
