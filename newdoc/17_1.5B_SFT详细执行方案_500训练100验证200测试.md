## 2 数据规格与职责

### data模块

```text
职责：筛选、语义分组、固定划分、恢复消息、构造监督标签、版本核验。
输入：config、原始D_dataset、公开提示词/schema、本地tokenizer。
输出：四个集合的消息文件、隐藏scenarios文件、manifest、同名中文md。
读取：原始轨迹和只读静态规则。
写入：output_root/data/。
不负责：模型训练、生成新数据、D6请求。
对应文件：training/10-5_sft/data.py、common.py。
```

同家庭和同隐藏目标的用户话改写归同组，忽略运行id和intent措辞；房间、设备与条件列表排序后计算SHA-256。重复组只保留一个代表，跨类别同组冲突直接失败。不能用“文件行号不同”证明两条数据独立。

| 集合 | 每类 | 总数 | 用途 |
|---|---:|---:|---|
| train | 100 | 500 | 参数更新 |
| validation | 20 | 100 | 每epoch验证、选择检查点 |
| test | 40 | 200 | 方案固定后最终评价，不用于调参或GRPO更新 |
| reserve | 依余量 | 194 | 备用，不参与本轮优化 |

训练代表先补足可用设备、动作、算子、keep和拒绝原因特征，然后按固定种子20261005补齐配额。验证与测试从剩余独立组中选取，四集合组id必须互斥。随机划分不等于所有行为已经覆盖：目前T4池没有READ_ONLY_DEVICE示范，这一限制继续记入报告和后续评测解释。

消息行只保存`sample_id / group_id / category / messages`；编码器只读取messages。`*_scenarios.jsonl`另存隐藏Scenario，供C评测，绝不能当成训练输入。

### 可见消息和标签

```text
system：现行A_policy + 公开工具表，只出现一次
user：用户原话
assistant：{"name":"...","arguments":{...}}
user：observation: 真实回执
...
assistant：finish的JSON；对话在这里结束

标签
  system / user / observation / 角色头 / padding -> -100
  每条assistant JSON + im_end -> 对应真实token id
```

给官方模板加入generation区域标记，只增加损失边界，不改变渲染字符串。逐条检查原始模板与训练模板字符串一致；逐段解码监督区域，必须正好等于助手JSON且包含结束token。这比只检查“存在assistant角色”更严格。

序列容量3072，padding按批内最长样本动态补齐至8的倍数；超长报错，不截断finish。预处理不写input_ids长期缓存，而保存可读消息，训练时重新核验并编码，避免tokenizer/模板变更后静默复用旧标签。

输入文件、提示词、schema、评测条件代码、tokenizer、配置和输出文件全部记指纹。版本变化或已导出文件被修改时拒绝加载；需要明确选择新产物目录或重新准备。

## 3 训练规格

### train模块

```text
职责：调用TRL/PEFT完成训练、验证、每epoch保存和检查点索引。
输入：config、mode、可选resume路径；已编码训练/验证样本。
输出：epoch检查点、selected_adapter、训练摘要、同名中文md。
读取：500训练与100验证；已有HF权重。
写入：独立smoke目录或sft-main目录。
不负责：最终200测试、语义裁判、数据合成。
对应文件：training/10-5_sft/train.py。
```

| 项目 | 本轮执行规格 |
|---|---|
| 框架 | Transformers 4.57.3、TRL 0.24.0、PEFT 0.18.0 |
| 参数方式 | LoRA，r16/alpha32/dropout0.05；q/k/v/o及gate/up/down线性层 |
| 精度和注意力 | BF16基础模型、SDPA、非重入gradient checkpointing |
| 批次 | micro4、累积2、单卡有效batch8；按用户最新要求调整 |
| 学习率 | 1e-4，AdamW，linear调度，完整训练warmup比例0.1 |
| 长度 | 3072；动态padding；禁止截断 |
| 混合 | 五类消息在同一Dataset，Trainer每epoch重排 |
| 时长上限 | 完整训练最多3epoch，以验证loss选择检查点 |
| 保存 | save_strategy=epoch，save_total_limit=None，保存优化器与随机状态 |
| 监督 | 自有正确labels经官方collator补齐，Trainer跳过重复预处理 |

500条、micro4意味着每epoch125个micro-batch，累积2后预计63次更新，最后一次只有4条；3epoch预计189次更新。实际以Trainer的global_step/epoch为准，不按“每条轨迹五次输出”额外乘五。4×2与旧2×4保持相同的有效batch；此轮按用户要求直接改配置，没有重跑GPU压力测试。

第一轮用验证loss选`selected_adapter`，但它不是环境成功率最好的证明。每个epoch都保留，可另外在验证环境中比较；没有用200测试集选择模型。

完整训练入口必须是`--mode train --confirm-full-training`。默认`check`只核对数据和计划。已有完整运行目录时拒绝覆盖，恢复必须指定该目录下的checkpoint，并且配置一致。

### 每epoch检查点规格

```text
checkpoint-STEP/
  adapter_model.safetensors
  adapter_config.json
  optimizer.pt
  scheduler.pt
  rng_state.pth
  trainer_state.json
  训练参数与tokenizer
  JSON对应中文md

checkpoint_index.json
  epoch / global_step / path
  config_sha256 / data_manifest_sha256 / adapter_sha256

selected_adapter/
  验证loss选中的adapter和tokenizer
```

保存回调核对上述必要文件，缺任何优化器、调度器或随机状态都报错。没有轮换删除历史检查点。adapter保留在仓库外，不保存或上传新的基础模型分发包。

## 4 评测规格

### evaluate模块

```text
职责：本地generate接入现行A，C/B运行真实多轮任务并统计分类型结果。
输入：基础模型或任意epoch adapter、集合、输出目录、语义裁判模式。
输出：trajectories.jsonl、summary.json和中文md。
读取：固定scenarios和本地权重；hidden task只给C。
写入：单独评测目录，已有结果不覆盖。
不负责：更新参数、伪造工具结果、默认发收费请求。
对应文件：training/10-5_sft/evaluate.py。
```

复用`DeepSeekPolicy`的消息状态流，只把客户端换为本地HF generate。输入依然是system、原话、assistant JSON、user observation；下一步根据真实B回执生成。greedy解码、每次最多192个新token，轮数保持Scenario中的10。

基础模型与adapter使用同一协议和相同固定集合，均不插入few-shot。过去GGUF few-shot分数留作历史信息，不与这一组HF zero-shot成绩混成同条件对照。

```text
默认semantic-judge=off
  T1/T2：C四项全过可以记完整成功
  T3/T4/T5：C未过记失败；C全过但D6未做记null/待审

显式semantic-judge=deepseek
  -> 复用D6三票
  -> 只有对/跳过且C全过才记完整成功
  -> system_failure记待确认，不伪装成成功
```

最终test必须额外确认。本轮仅在训练集合每类选一条检查学生生成接口，不读最终200条的模型成绩，不调用DeepSeek。

## 5 预测试规格与通过标准

### preflight和测试模块

```text
职责：对代码和实际GPU路径形成验证闭环，不替代正式效果评测。
输入：固定配置；可选gpu-smoke或已有smoke重用路径。
输出：pytest结果、preflight_report、epoch adapter核对结果。
读取：数据、训练教师示范、真实保存的adapter和状态。
写入：pytest临时文件、独立smoke产物、小型报告。
不负责：500条完整训练、最终测试、GRPO。
对应文件：preflight.py、test_pipeline.py及同名md。
```

```text
数据与监督
  配额正确，四集合隔离，输入行顺序不影响划分
  所有assistant段和EOS得到监督，用户/观察不进入loss
  模板文本不变，超长不裁剪，文件篡改可发现

环境契约
  每类一条训练教师轨迹重放，C四项全过

最小GPU路径
  一个micro-batch的最长训练样本（当前四条） + 两条验证样本
  两个epoch，每epoch一个micro-batch，合计两次更新
  loss有限、LoRA确有可训练参数、显存峰值被记录
  每epoch保留adapter和优化器/随机状态

重载与接口
  每个epoch以及selected adapter独立重载
  保存与重载后的每个adapter张量零误差一致
  每类一条训练任务的真实学生交互可执行
  本地generate调用无运行异常
  基础权重文件SHA-256不变
```

初次旧2×4配置GPU预测试只用了两条最长轨迹，发现多adapter追加加载会有FP32到BF16的中间精度转换，因此重载验证采用与正式评测相同的“每个检查点独立加载”路径。没有通过放宽比较误差掩盖转换；历史结果仍保留，不能视为新4×2配置的显存实测。

`--reuse-smoke`允许在已经完成两次更新的目录上继续修复后的检查，不重复训练。它必须位于output_root下、配置一致且已有summary证明两次更新。完整训练模式和测试集确认开关的自动测试也必须通过。

## 7 通过预测试后仍不能保证什么

通过只能证明当前数据与配置下，处理、损失、GPU更新、epoch保存、独立adapter重载和环境接口能够跑通。两次更新和五条训练任务不能证明500条SFT一定提高泛化成功率。

完整500条训练、完整验证环境比较、200条最终测试、D6完整成功率以及中断后的正式恢复训练，本轮不执行。READ_ONLY_DEVICE缺示范的风险仍保留。用户确认后先记录同协议基础模型验证基线，再完整训练；最终测试只用于冻结方案后的结果。
