# `.env.deepseek` 配置说明

## 用途

给新包 `new_demo/` 的 DeepSeek 客户端读。A 与 D2/D3/D6 共用一个文件，用字段区分两路。本文件只说明字段，不含密钥。

## 输入

真实密钥只出现在同目录 `.env.deepseek` 的 `DEEPSEEK_API_KEY=` 后面。

```text
DEEPSEEK_API_KEY
  必填。空则客户端启动时报 CONFIG_ERROR，不准静默跳过。

DEEPSEEK_BASE_URL
  默认 https://api.deepseek.com
  客户端再拼 /v1/chat/completions

DEEPSEEK_MODEL
  未单独指定 A / external 模型时的后备名
  默认 deepseek-chat

DEEPSEEK_A_MODEL
  仅 D5 的 policy.respond 使用
  默认跟 DEEPSEEK_MODEL

DEEPSEEK_A_TEMPERATURE
  仅 role=A
  默认 0.6

DEEPSEEK_EXTERNAL_MODEL
  D2 / D3 / D6 使用
  默认跟 DEEPSEEK_MODEL

DEEPSEEK_EXTERNAL_TEMPERATURE
  仅 role=external
  默认 0.7

DEEPSEEK_TIMEOUT
  单次请求秒数，默认 120

DEEPSEEK_MAX_RETRIES
  传输级重试次数，默认 3
  只对网络 / 408 / 429 / 5xx 重试
```

这一次不设 `DEEPSEEK_A_MAX_TOKENS`，也不设 `DEEPSEEK_MAX_TOKENS`。客户端请求体两路都不写 `max_tokens`。

## 两路怎么用

```text
role=A
  读 DEEPSEEK_A_MODEL、DEEPSEEK_A_TEMPERATURE
  请求体不带 max_tokens
  每轮只输出一个工具或 finish
  只在停闸确认之后的 D5 / C.run 里出现

role=external
  读 DEEPSEEK_EXTERNAL_MODEL、DEEPSEEK_EXTERNAL_TEMPERATURE
  请求体不带 max_tokens，不截断
  D2 第一次、D2 第二次、D3、D6 必须走这条
```

V2 闸 1 的 `DeepSeek_test_roles.py` 要断言：A 与 external 的请求体都不含 `max_tokens`。

## 使用方式

```text
1. 打开 /root/autodl-tmp/new_demo/.env.deepseek
2. 只填写 DEEPSEEK_API_KEY= 后面的密钥
3. 不要把密钥粘到 Python、JSONL、日志、对话或 Git
4. 代码只读这个文件，不读 homeflow_demo/.env.deepseek
```

## 输出

本配置不产生训练数据。原始响应写入：

```text
new_demo/data_raw/api/
```

记录可以含 request_id、role、model、usage、正文；禁止含 Authorization 头和 API key。

## 安全

```text
.git 已忽略 **/.env.deepseek
空密钥直接失败
日志只打 request_id、模型名、错误码
旧 demo 的 env 不再作为新管线入口
```
