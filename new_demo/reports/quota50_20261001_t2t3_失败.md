# T2 / T3 失败二十例

> 来源：`new_demo/runs/quota50_20261001/`（含补跑并入）
> 这批进集已经是 T2 50、T3 50。下面只看没进集的。
> T2 抽 10 条，T3 抽 10 条，按类型挑，不把同一句 D3 拒词抄十遍。

这批 T2 没进集，主要死在三处：D3 认为 intent/用户话和 hidden 设备对不齐；三条 condition 把 10 轮用完没 finish；范围题 A 只挪一小步。T3 主要死在：方向对但 s0 已经成立；话里又闷又潮，D3 只认一边；A 把「潮」做成开热水器，或只开机不改温度。

```text
  D3 TARGET_NOT_COVERED   约 50    清单肥、房间写飞、keep 说成方向
  D3 EXTRA_INTENT          3       闲话当成第二件事
  D2 keep 用了 ge          1
  D4                       5       没有的冰箱 / 台灯没有 mode
  轨迹 C-1 C-4            16       10 轮写完没 finish

这批 T3 失败怎么分布

  轨迹 C-2                约 44    关加湿器没关；ge/le 只加两度或只开机
```

## T2 十例

### 1. D3 画像家具写进 intent，本轮没有走廊

```text
p02  房间：卧室 / 客厅 / 书房 / 厨房 / 走廊
用户话  十点以后把客厅电视关掉，走廊夜灯别亮着，脏衣服明天丢进厨房洗碗机开节能洗，卧室加湿器先别动。
intent  十点后客厅电视必须关、走廊灯不要亮，脏衣服隔天丢进洗衣机开快洗，卧室加湿器先别动
cond    客厅电视关掉；走廊夜灯关掉；厨房洗碗机 mode=eco
keep    卧室加湿器关上

D3  TARGET_NOT_COVERED
```

intent 里是洗衣机快洗，condition 写成洗碗机节能。画像「十点后关电视、走廊灯」把走廊灯写进来了；用户话跟 intent 也不全同。D3 按清单对不齐拒。

### 2. D3 intent 多写了主灯暗档，hidden 没有这条

```text
p07  房间：卧室 / 客厅 / 书房 / 厨房 / 走廊
用户话  我九点半批完作业就歇着，嗓子干把卧室加湿器打开，卧室主灯调暗一点，卧室电视关掉，客厅空调调高一点，厨房冰箱别动。
intent  九点半批完作业就休息，嗓子干要开加湿器，卧室主灯调到暗档，卧室电视关掉，客厅空调调高一点，厨房冰箱别动
cond    卧室电视关掉；客厅空调 target ge 25；卧室加湿器打开
keep    厨房冰箱 4.0

D3  TARGET_NOT_COVERED
```

用户话和 intent 都有「主灯调暗」，conditions 三条里没有主灯。T2 原则是 intent 设备 = conditions ∪ keep，这里多了一台。

### 3. D3 电视写错房间

```text
intent  晚上九点准备睡，客厅电视声音要小，卧室主灯用暗档，空调不要太冷，泡脚时热水器不要太烫
cond    次卧电视 level le 30；主卧空调 target ge 24；卫生间热水器 target le 45

D3  TARGET_NOT_COVERED
```

用户话说次卧电视，intent 写成客厅电视，还多了主灯暗档。hidden 三条和嘴里那几件对不上。

### 4. D3 夜班回来：洗衣机写成了排气扇

```text
p03  房间：卧室 / 厨房 / 卫生间
用户话  我夜班回来有点累，先把卫生间热水器打开，再把卫生间洗衣机也开上，卧室加湿器先别动。
intent  夜班回来先开卫生间热水器，再把卫生间排气扇打开，卧室加湿器先别动
cond    热水器打开；洗衣机打开
keep    卧室加湿器开着

D3  TARGET_NOT_COVERED
```

condition 是洗衣机，intent 是排气扇。用户话跟 condition 一致，D3 看 intent 对不上就拒。问题出在 D2-1 的 intent，不是用户话。

### 5. D2 keep 写成「别太低」，用了 ge

```text

intent  晚上加湿器开着，主灯用暗档，冰箱不要太低，主卧电视关掉
cond    主卧加湿器打开；主灯 mode=dim；主卧电视关掉

程序  T2 operator must be one of ['eq']
```

keep 只许 eq。模型把「冰箱别太低」写成 ge，程序在 D2 拦住，没有用户话。这是 keep 和范围题混了。

### 6. D4 家里没有冰箱


### 7. D4 台灯没有 mode，却写 dim

## T3 十例

### 1. D2 already holds：闷 → le 26，s0 已经 14.5

```text
p24  房间：卧室 / 客厅 / 书房 / 厨房 / 走廊
intent  屋里闷得发燥
cond    书房空调 target le 26
s0      书房空调 target=14.5  已经 ≤26

程序  T3 condition already holds on s0
没有用户话
```

方向对（热 → 小于等于），闭区间里已经成立。提示词要求换设备或换感受，这条没换。

### 2. D2 already holds：潮 → 关加湿器，本来就关着

```text
p14  房间：卧室 / 客厅 / 卫生间
intent  屋里闷得身上黏糊糊的
cond    客厅加湿器 on eq false
s0      客厅加湿器 已经关着

程序  T3 condition already holds on s0
```

潮 → 关掉，对。机子已经是关的，题面没有变化，程序拦。

### 3. D2 already holds：干 → 开加湿器，本来就开着

```text
p08  房间：卧室 / 客厅 / 书房
```

和上一条对称。干/潮只剩开关，s0 随机到终态上就出不了题。

### 4. D2 already holds：冷 → ge 26，s0 已经 28


冷 → 大于等于，对。边界已经成立。本可以改写加湿器「干」，没走。

### 5. D3 闷+潮，hidden 关加湿器，D3 按闷要空调

```text
p11  房间：卧室 / 客厅 / 厨房 / 卫生间 / 书房
用户话  这屋里闷得身上都潮乎乎的，待着真难受。
intent  屋里闷得身上发潮
cond    书房加湿器关掉（当时开着）

D3  TARGET_NOT_COVERED
```

潮 → 关加湿器，方向对。话里同时有「闷」，D3 按热应对空调，判成目标和 task 相反。这类在 T3 的 D3 失败里占大多数。

### 6. D3 黏+闷，hidden 走了空调降温

```text

用户话  身上黏糊糊的，闷得有点喘不过气。
intent  身上黏糊糊的，闷得慌
cond    书房空调 target le 24   s0=25.5

```

和上一条反着：hidden 按闷降温，D3 听到黏，要关加湿器。一句里两个感受，D3 只认一个。

### 7. 轨迹：人说潮，A 说没有除湿机，加湿器没关

```text
sc_T3_011
用户话  身上黏糊糊的发潮，翻来覆去睡不踏实。
cond    卧室加湿器关掉    s0 开着
A       observe → inspect 卧室 → finish refused
        「卧室没有除湿设备，只有加湿器（会加潮），未做任何操作。」
        reason_code=UNSUPPORTED_ACTION

C-2  加湿器仍是开    C-4 期望 completed，来了 refused
```

hidden 要的就是关掉加湿器。A 把加湿器理解成「会加潮所以不能动」，没执行 turn_off。

### 8. 轨迹：人说潮，A 去开热水器

```text
cond    客厅加湿器关掉    s0 开着

```

模糊指令被解成洗澡。hidden 是关客厅加湿器，A 没碰那台机。

### 10. 轨迹：冷 ge 26，A 调到 24

## 二十条合在一起看

```text
T2 出题
  intent 设备必须 = conditions ∪ keep
  本轮没有的房间、冰箱、走廊不要写
  keep 只能 eq，不能「别太低」
  主灯是 mode，台灯是 level，不要写反

T2 轨迹
  三台各 inspect+写，10 轮不够 finish
  「调小一点」对 le 30，A 只收到 60，C-2 挂

T3 出题
  方向对但 s0 已成立 → 换设备，不要硬写
  闷+潮同一句，D3 会只认一边

T3 轨迹
  潮 = 关加湿器，不是开热水器，也不是「没有除湿机」就拒绝
  闷/冷的 ge le，要改 target，只开机不够
```
