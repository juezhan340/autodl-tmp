## A 智能体任务适配

### A1 多轮任务规划压成单轮推理（2509.20616）

论文：*Training Task Reasoning LLM Agents for Multi-turn Task Planning via Single-turn Reinforcement Learning*

任务：长程多轮任务规划，在 Robotouille 基准上评测。多轮 RL 的老问题是回合级奖励稀疏、长程信用分配难、交互开销大。

做法：把多轮规划拆解成一个个单轮"给定当前状态，选最优下一个动作"的推理题，每一步用专家轨迹定义二值奖励（是否与专家动作一致），再拿这个稠密可验证奖励做单轮 GRPO。论文还从理论上证明：单轮推理成功率的提升是多轮成功概率的下界，并且能泛化到更短horizon的子任务。作者另外做了非专家噪声轨迹的鲁棒性消融。

结果：1.5B 模型在长程规划任务上做到 70% 成功率，稳定超过参数量到 14B 的基线，而且完成步数更少。

对 HomeFlow 的参考：这篇和你们把多轮交互压成 A-policy 单步决策的路线几乎同构，是最直接的最近邻相关工作。它证明了"单步推理对了，多轮就有下界保证"，正好可以给你们的 A-policy 设计当理论背书；它的专家轨迹二值奖励，和你们 condition/request 对齐检查是同类信号。

链接：https://arxiv.org/abs/2509.20616

### A2 小模型工具调用（2509.04518）

论文：*Advancing SLM Tool-Use Capability using Reinforcement Learning*

任务：小模型做函数调用 / 工具调用，输出结构化 JSON。

做法：GRPO + 结构化奖励系统，奖励拆成三层：输出是否是合法 JSON、工具是否选对、参数是否精确。用一套精心设计的奖励把"格式约束"和"语义正确"分开监督。

结果：SLM 的工具调用准确率显著提升，训练与推理开销都远低于大模型路线，适合资源受限部署。

对 HomeFlow 的参考：奖励拆分方式和你们 A-policy 的检查维度（工具名、参数、格式）一一对应。这篇可以引用来说明"小模型工具调用能力可以靠 GRPO 补"。

链接：https://arxiv.org/abs/2509.04518

### A3 任务-工具意图校验（2610.03213）

论文：*Toward SLM-based agentic task-tool intent matching*

任务：给智能体的每一次工具调用做"这一步是否服务于任务意图"的校验。任务和工具跨多个 MCP 服务器，一次允许的调用未必符合任务意图。

做法：构建多工具任务数据集，把 SLM 训练成任务-工具相关性分类器：输入任务和本次工具调用，输出相关性信号。训练路线是 prompt 优化 → SFT → GRPO 三段。

结果：SLM 可以低延迟、本地化地对每次调用做监督，弥补传统授权机制只看"允不允许"、不看"合不合理"的空档。

对 HomeFlow 的参考：你们评测里"工具选错、意图漂移、答非所问"这类失败，可以用同样的逐次调用监督思路做自动检测，比事后人工看轨迹便宜。

链接：https://arxiv.org/abs/2610.03213

### A4 闭环环境里的小模型（2505.03238，RobotxR1）

论文：*RobotxR1: Enabling Embodied Robotic Intelligence on Large Language Models through Closed-Loop Reinforcement Learning*

任务：机器人 / 自动驾驶场景的具身智能，需要模型在端侧闭环决策。

做法：把 R1-Zero 的思路从静态数学数据搬到闭环环境：模型与环境交互、根据环境反馈学习推理，而不是只靠蒸馏大模型做 SFT。训练目标是"在交互中学"，环境反馈就是奖励来源。

结果：Qwen2.5-1.5B 在自动驾驶设置下比 SFT 基线高 20.2 个百分点；Qwen2.5-3B 的控制适配得分 63.3%，超过云端 GPT-4o 的 58.5%。

对 HomeFlow 的参考：小模型靠闭环反馈反超大模型的直接证据。你们的 HomeEnv 本身就是闭环环境，这篇可以支撑"环境交互训练 > 纯 SFT"的叙事。

链接：https://arxiv.org/abs/2505.03238

## B 智能家居域

### B1 记忆驱动的家居控制与 PRISM（2604.10110）

论文：*Trust Your Memory: Verifiable Control of Smart Homes through Reinforcement Learning with Multi-dimensional Rewards*

任务：记忆驱动的智能家居设备控制，包括记忆的添加、更新、删除、使用。已有基准要么只测即时控制，要么只测开放域记忆检索，测不了这两者的结合。

做法：先发布 MemHomeLife（脱敏真实长期用户交互日志）和 MemHome 基准。方法 PRISM 把任务正确性拆成多个一致性维度（输出格式、记忆逻辑等），每个维度由一个 LLM verifier 判定，奖励用乘法组合：任何一个维度不过关，整条轨迹奖励清零（veto 设计）。另外加了一个 prefix confidence 辅助奖励，用正确前缀的 token 对数概率鼓励模型在"记忆/重写/不重写"这类前缀决策上更可靠。

结果：在 MemHome 上超过 Mem0、Memory-R1 等基线，8B 规模最多提升 15.43%。线上做了长达一个月的 A/B 测试，覆盖数百万月查询量。

对 HomeFlow 的参考：veto 式奖励和你们 false_finish / unsafe 一票否决是同一种设计哲学；多维 verifier + 前缀置信度这两个技巧都可以平移到 A-policy 的监督上。

链接：https://arxiv.org/abs/2604.10110

### B2 小米智能家居命令理解 MiCU（2606.01099）

论文：*MiCU: End-to-End Smart Home Command Understanding with Large Language Model*

任务：家居命令理解，难点是模糊指令（"make the bedroom cozy"）和领域数据稀缺。

做法：三步训练管线。先用户日志 + LLM 自动合成训练数据；然后课程学习，从通用语料继续预训练开始，SFT 从简单样本逐步过渡到难样本；再用 DeepSeek-R1 生成的领域 CoT 做冷启动，随后用 DAPO 强化学习、以领域思考规则引导推理。另有一套 token 压缩技术，把冗长的设备描述压成单个特殊 token，得到低成本变体 MiCU-fast。

模型：Qwen3-4B-Instruct。

结果：比规则方法高 28.29%，比最好的 LLM 基线高 20.01%。token 压缩让 prompt 长度减少 31.9%，精度只掉 0.6%。已上线小米 Home，用户纠正率下降 1.57%，人工审核准确率提升 32.05%，日均约 170 万页面浏览。

对 HomeFlow 的参考：这是目前能看到的最完整的智能家居落地训练管线，课程学习 + CoT 冷启动 + RL 的组合可以直接对标。注意它用的是 DAPO，而不是 GRPO。

链接：https://arxiv.org/abs/2606.01099

### B3 小米家居多模态模型 MiMo-VL-Miloco（2512.17436）

论文：*Xiaomi MiMo-VL-Miloco Technical Report*

任务：家居场景的多模态理解，手势识别、家庭场景理解，同时保持通用多模态能力。

做法：基于 MiMo-VL-7B，两阶段训练：SFT 加基于 GRPO 的强化学习，混入多领域数据，加入 CoT 监督和 token 预算感知推理，用数据效率换专业化和通用性的平衡。

结果：家居场景理解 F1 领先，Video-MME、MMMU-Pro 等通用基准也有提升；开源了权重（含 GGUF 量化）、评测工具包和训练配方。

对 HomeFlow 的参考：家居域目前少有的开源 VL 基线，7B 规模比你们大，但两阶段 SFT+GRPO 的结构、以及"专业化不牺牲通用性"的结论值得引用。

链接：https://arxiv.org/abs/2512.17436

### B4 1-bit 模型做灯光节能控制（2512.20623）

论文：*BitRL-Light: 1-bit LLM Agents with Deep Reinforcement Learning for Energy-Efficient Smart Home Lighting Optimization*

任务：住宅灯光控制，同时优化能耗、舒适度和昼夜节律，跑在边缘设备上。

做法：1-bit 量化的 Llama-3.2-1B 加 DQN 强化学习，部署在树莓派 4 上，通过 Google Home / IFTTT 接自然语言命令，并从用户手动覆盖行为里学习偏好。多目标 RL 平衡三个目标。

结果：比规则系统节能 32%，推理延迟低于 200ms，用户满意度 95%，能耗比全精度模型低 71.4 倍。

对 HomeFlow 的参考：一个极端边缘部署案例，动作空间用的是 DQN 而不是 GRPO。如果以后要讨论"本地小模型跑家居控制"的可行性，这是现成证据。

链接：https://arxiv.org/abs/2512.20623

## C 垂直领域小模型适配

### C1 SQL 重写与 SQL-GRPO（2604.06804）

论文：*LASER: A Data-Centric Method for Low-Cost and Efficient SQL Rewriting based on SQL-GRPO*

任务：SQL 查询重写，把查询改写成语义等价但执行更快的版本，用于数据库优化。

做法：数据侧先用 SQL-MCTS 造数据，把规则引导的反模式（anti-pattern）和 LLM 变异结合，从种子查询演化出执行验证过的大规模慢查询语料。算法侧提出 SQL-GRPO：锚定组优势（Anchored Group Advantage）改进优势估计，复杂度自适应动态 rollout 按查询复杂度分配探索预算。

模型：Qwen3 系列小模型。

结果：执行效率超过规则系统和大模型方案，零样本迁移能力强，额外开销很小。

对 HomeFlow 的参考：数据合成（MCTS 演化 + 执行验证）和任务奖励设计的配合，和你们蓝图管线造数据、再用环境验证的思路一致。

链接：https://arxiv.org/abs/2604.06804

### C2 2B 遥感多模态 TinyRS-R1（2505.12099）

论文：*TinyRS-R1: Compact Multimodal Language Model for Remote Sensing*

任务：遥感图像任务——分类、视觉问答、视觉定位、开放问答，目标硬件是边缘设备。

做法：基于 Qwen2-VL-2B 的四阶段管线：百万级卫星图预训练 → 视觉指令微调 → 用自建推理数据集做 CoT 微调 → GRPO 对齐。

结果：2B 模型在多个任务上追平或超过 7B 遥感模型，显存和延迟约为三分之一。分析发现 CoT 对空间定位和场景理解帮助大，而低延迟 VQA 更适合非推理版本。

对 HomeFlow 的参考：小模型领域适配最完整的四阶段模板；"推理能力对定位类任务收益更大、对低延迟任务反而是负担"这个结论，对你们决定哪些任务上多步推理有直接参考价值。

链接：https://arxiv.org/abs/2505.12099

### C3 医疗文本生成的方法对比（2607.13430）

论文：*Exploring Post-Training Alignment of Small Language Models for Biomedical Data-to-Text Generation: A Case Study of Medication Leaflet*

任务：把复杂生物医学数据转成患者能读懂的药品说明书文本。

做法：用 Qwen 系 SLM 系统对比 SFT、DPO、ORPO、GRPO 四种后训练方法；另外整理 openFDA 药品标签数据来测跨数据集泛化。

结果：对齐后的 SLM 超过 GPT-5 等专有模型；ORPO 优于 SFT 基线；GRPO 在跨数据集泛化上最稳。

对 HomeFlow 的参考：一篇现成的"四种对齐方法在同一领域任务上对比"的实验模板，结论支持"GRPO 的收益主要体现在泛化"。

链接：https://arxiv.org/abs/2607.13430

### C4 金融建议生成（2608.11787）

论文：*GRPO for Financial Advice Generation: Outperforming Commercial LLMs under CATE Evaluation*

任务：从业务记录生成可执行的金融建议，要求数值推理、领域知识和风险判断兼顾。

做法：把建议生成建模成 RL 问题，用 GRPO 微调；奖励是 LLM-as-judge 的多维二值 rubric 加一道安全门。因为 judge 打分不能证明真实业务价值，论文额外用一个基于双重稳健估计的 CATE（条件平均处理效应）做独立因果审计。

结果：因果审计下，训练后模型的毛利润提升约为最强商业基线的两倍（0.0228 对 0.0104），下行风险最低。一个有意思的发现：judge 评分和因果审计对基线的排序并不一致，说明两者捕获的信号不同。

对 HomeFlow 的参考：奖励设计 + 独立评估分离的范式，以及"别完全信 LLM 打分"的实证提醒。

链接：https://arxiv.org/abs/2608.11787

### C5 专用翻译小模型 CAT-Translate（2606.21413）

论文：*CAT-Translate: Building Compact Open-Source Models for Japanese-English Translation*

任务：日英双向翻译，重点看真实业务场景（商业、法律、医疗、金融、专利）而不是通用 WMT 榜单。

做法：做 0.8B、1.4B、3.3B、7B 四个规模的专用模型，合成平行语料，两阶段 SFT 加多目标 GRPO。

结果：通用 WMT 基准上多语大模型仍强，但真实领域基准上这些小专用模型反超。

对 HomeFlow 的参考："窄语言对 / 窄领域专用模型 > 通用大模型"的实践证据，和你们"专用小模型做家居任务"的定位一致。

链接：https://arxiv.org/abs/2606.21413

### C6 长文档 QA 的 LiteCoST（2603.29232）

论文：*Long-Document QA with Chain-of-Structured-Thought and Fine-Tuned SLMs*

任务：长而嘈杂的文档问答，模型需要把分散的证据整理成结构化输出（表格、图、片段）再回答。

做法：两支柱。CoST 模板让强 LLM 生成"结构化思维链 + 结构化输出"，过程包含结构最小化、实体与单位归一、记录对齐、序列化、验证修正，产出可审计的监督数据。SLM 两阶段训练：SFT 做结构对齐，然后 GRPO，使用答案质量、格式质量、过程一致性三重奖励。

模型：3B / 7B。

结果：质量接近 GPT-4o 和 DeepSeek-R1（671B），延迟低 2~4 倍。

对 HomeFlow 的参考："结构先行的数据合成 + 过程奖励"的组合，和你们蓝图管线里场景结构化的做法同源。

链接：https://arxiv.org/abs/2603.29232

### C7 工业质检 VQA 的任务感知 GRPO（2609.21276）

论文：*Beyond Exact Match: Task-Aware GRPO for Cross-Domain PCBA Visual Question Answering*

任务：电路板组装的跨域视觉问答，输入有标准文件衍生样本和真实产线图像，题型有选择题和计数题，输出空间异构。

做法：把标准、真实、辅助三类数据统一成指令格式，构建带视觉证据的推理轨迹。算法上提出 Task-Aware GRPO：选择题用多成分语义奖励，计数题用距离感知奖励，另加格式奖励。推理端组合答案选项语义一致性修正、自洽投票和多模型仲裁。

结果：官方 PCBA Standard-to-Real 挑战榜总分 83.24。

对 HomeFlow 的参考：题型不同就换奖励（数值题用距离奖励，而不是精确匹配），正好对应你们 condition 里 eq 与 le/ge 要区分处理的设计。

链接：https://arxiv.org/abs/2609.21276

### C8 机器翻译的 MT-R1-Zero（2504.10160）

论文：*MT-R1-Zero: Advancing LLM-based Machine Translation via R1-Zero-like Reinforcement Learning*

任务：机器翻译，输出格式灵活、难以用显式规则自动评分，是把 R1-Zero 范式搬到翻译的早期探索。

做法：不要 SFT、不要冷启动，直接做 R1-Zero 式 RL；奖励用规则 + 指标混合（rule-metric mixed reward），让模型在训练中自行涌现推理行为。论文系统分析了初始化与奖励设计对训练动态的影响。

模型：3B / 7B。

结果：3B 版本在 WMT24 英中上平均超过 TowerInstruct-7B 约 1.26 分；7B 版本与 GPT-4o、Claude-3.5-Sonnet 持平；OOD 翻译与低资源设置泛化良好。

对 HomeFlow 的参考：说明非严格可验证任务也能用纯 RL，但要用混合奖励补足规则的空缺；相对 SFT→GRPO 路线风险更高。

链接：https://arxiv.org/abs/2504.10160

### C9 痴呆症护理智能体与 T²-GRPO（2606.08875）

论文：*Can the Environment Speak for Itself? T²-GRPO: A Turn-Trajectory Group Relative Policy Optimization for Caregiver Agents*

任务：长程护理智能体，在痴呆症照护场景里要同时兼顾任务目标、患者当下的痛苦与抗拒等环境动态。

做法：把护理 RL 拆成两个奖励horizon：回合级奖励直接从环境状态转移里算（患者痛苦度、抗拒度的变化），轨迹级奖励做长程评估，两者用独立的中心化排序归一化组合，再加一个二值硬否决保证安全。奖励来自冻结的痴呆症患者模拟器，不依赖外部 LLM 评估。

结果：在痴呆症照护任务上超过竞争基线，能同时处理即时反馈、长期结果和安全约束。

对 HomeFlow 的参考：环境直接给回合级奖励的做法，和 HomeFlow 用环境规则算逐步奖励的思路一致；它的"双 horizon 奖励 + 硬否决"可以对照你们 success/progress/evidence/false_finish 的权重设计。

链接：https://arxiv.org/abs/2606.08875

## D 反例与边界

### D1 SFT 还是 RL：工具调用智能体的对照研究（2609.17848）

论文：*SFT or RL for Tool-Calling Agents? A Controlled Study Across Data, Method, and Scale*

做什么：拿 6 个 Qwen3 模型（0.6B 到 32B），在工具调用任务上系统对比 SFT（LoRA）、GRPO、SFT→GRPO 三条路线，同时看分布内性能和跨数据集迁移。

结论：分布内 SFT 在 18 个设置里赢 15 个，是全程最强的方法；跨数据集迁移上两者接近，GRPO 赢 54 个设置里的 29 个，但平均领先不到 1 分；SFT→GRPO 很少拿第一。数据混合能稳定提升迁移且几乎不损失分布内性能。LoRA 优于全参微调，因为更少破坏预训练的智能体行为。

对 HomeFlow 的参考：对"要不要上二期 GRPO"最直接的参考。这篇的建议是：GRPO 的价值要用跨场景/跨数据集指标来验收；如果只看同分布测试集，可能看不到收益（你们一期 +1.5 个点的情况类似）。

链接：https://arxiv.org/abs/2609.17848

### D2 连续控制上的 GRPO 塌缩（2607.21626）

论文：*Discrete Action Space as a Prerequisite for GRPO Convergence in Small-Model Continuous Control*

做什么：用 GRPO 微调 Qwen-0.5B 做四旋翼无人机的连续控制（25Hz 速度控制）。

结论：原版 GRPO 训练 60 步内就塌缩到零动作，成功率 0%，熵从 0.35 掉到 0.03。去掉 jerk 惩罚项或去掉 KL 锚点都能避免熵塌，但都没学会任务。把动作接口换成 5 档离散 PID 预设之后才收敛：64 步时成功率 98.6%，256 步达到 100%。

对 HomeFlow 的参考：连续动作空间会让 GRPO 变得不稳定；你们的 A-policy 输出是离散工具调用，这一点上风险较小，但"动作/输出空间的设计决定 GRPO 能不能收敛"这个结论值得在方法部分写一句。

链接：https://arxiv.org/abs/2607.21626

## 5 共性总结与对 HomeFlow 的启示

数据来源的五种主流做法：

```text
用户日志 + LLM 合成   → MiCU（B2）
MCTS 演化 + 执行验证  → LASER（C1）
专家轨迹              → 单轮任务规划（A1）
LLM 生成 + 结构模板   → LiteCoST（C6）
真实脱敏日志          → MemHome（B1）
```

奖励设计的层次：

```text
第一层 格式    输出是否合法（JSON/XML/模板）
第二层 结果    任务是否完成、答案是否正确
第三层 过程    中间步骤是否合理、记忆是否用对、前缀是否选对
特殊机制       veto（任一关键维度不过关 → 0 分）  B1
               距离奖励（数值题按接近程度给分）    C7
               硬否决（安全约束）                  C9
               因果审计（独立于奖励的验收）        C4
```

给 HomeFlow 的五条可操作结论：

```text
1 A1 是最接近的相关工作，1.5B + 单轮 GRPO + 专家轨迹奖励，和你们的设定几乎一致，
  引用它可以直接省掉一大段"为什么可行"的论证。

2 B1 的 veto 奖励和你们 false_finish/unsafe 一票否决同源；它的多维 verifier
  可以映射到你们 A-policy 的 condition/request 检查。

3 D1 提醒：GRPO 的验收指标应该包含跨场景泛化。你们一期 89.5% vs SFT 88.0%
  的增幅如果只算同分布，价值会被低估，建议补一个跨数据集评测。

4 C7 证明"题型不同 → 奖励不同"是主流做法，你们 condition 为 eq 与 le/ge
  时分别对齐精确指令与范围指令的设计，方向是对的。

5 arXiv 上 GRPO + 智能家居目前 0 篇，B 组四篇要么用 DQN、要么用 DAPO、
  要么只做 SFT+GRPO 的 VLM。把 GRPO 用在多轮设备控制任务上，
  在检索范围内还没有人占位。
```
