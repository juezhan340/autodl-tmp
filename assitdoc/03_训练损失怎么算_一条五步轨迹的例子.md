# 训练损失怎么算：以一条 5 步轨迹为例（1.5B SFT 那轮）

> 对应训练：2026-10-05 的 Qwen2.5-1.5B LoRA SFT（500 训练 / 100 验证 / 200 测试，3 个 epoch）
> 依据：`training/10-5_sft/data.py`、`train.py`、`config.json` + `newdoc/1004推进文档/08、09` 的实际日志
> 写给初学者：先讲原理，再对着真实数字。本文不重新训练。

## 0 先纠正三个容易误会的小点

```text
① "每一步都做一次 SFT 对齐与评测" —— 没有这回事。
   一条轨迹 = 一条训练样本；5 步的监督信号在一次前向里全部算完，
   不是分 5 次训练，每一步也没有单独的"评测"。

② "4 条一小组、累积 2 次 = 8 条轨迹做一次参数更新" —— 这个对。
   config：micro_batch_size=4、gradient_accumulation_steps=2
   500 条 / 8 = 62.5 → 每个 epoch 63 次更新；3 个 epoch = 189 次。

③ loss 只算"模型自己说的那句话"（assistant 的 JSON + 结束符 im_end）。
   用户话、工具回执（observation）、系统提示、角色头、padding
   全部标成 -100 —— 不参与 loss，只作为上下文。
```

## 1 一条轨迹在训练里长什么样

用一条"关卧室台灯"的轨迹举例，它有 5 个 assistant 步：

```text
[system]     A_policy 全文 + 工具表                                  ← 上下文，不算 loss
[user]       把卧室台灯关掉。                                         ← 上下文，不算 loss
[assistant]  {"name":"observe_home","arguments":{}} <im_end>          ← 算 loss
[user]       observation: {"rooms":[...]}                             ← 上下文
[assistant]  {"name":"inspect_room","arguments":{"room_id":"room_bedroom"}} <im_end>  ← 算 loss
[user]       observation: {"room":{"devices":[...]}}                  ← 上下文
[assistant]  {"name":"inspect_device","arguments":{"device_id":"device_bedroom_lamp"}} <im_end>  ← 算 loss
[user]       observation: {"device":{"state":...,"actions":[...]}}    ← 上下文
[assistant]  {"name":"execute_action","arguments":{"device_id":"device_bedroom_lamp","action":"turn_off","params":{}}} <im_end>  ← 算 loss
[user]       observation: {"changed":true,"state_after":{"on":false}} ← 上下文
[assistant]  {"name":"finish","arguments":{"summary":"卧室台灯已关闭。","outcome":"completed"}} <im_end>  ← 算 loss
```

代码里怎么做到的（`data.py`）：

```text
tokenizer.apply_chat_template(..., return_assistant_tokens_mask=True)
  → 每个 token 一个 0/1 标记：1 = assistant 生成的（含 im_end），0 = 其他
labels = [token if 标记==1 else -100]

代码还会逐段校验，保证监督区域正好是"模型该学会输出的东西"：
  · 每段 assistant 的最后一个 token 必须是结束符（im_end）
  · 去掉结束符后解码，必须与原始 JSON 完全一致（不多不少）
```

  · 去掉结束符后解码，必须与原始 JSON 完全一致（不多不少）

```

## 2 损失怎么算：逐 token 的"猜下一个"

大语言模型训练的本质：每个位置都在猜"下一个 token 是什么"。
训练时把真实答案（正确的下一个 token）放在旁边，模型给出概率 p，
这个位置的损失就是 -ln(p)：猜得越准，损失越小；猜错了，损失越大。

用第一步 `{"name":"observe_home","arguments":{}}` + im_end 做例子
（下面的数字是为了演示编的，不是日志里的真实值）：

```text
要预测的 token          模型给正确答案的概率    该位置的 loss = -ln(p)
{                       0.99                    0.010
"name"                  0.97                    0.030
:                       0.99                    0.010
"observe_home"          0.90                    0.105
,                       0.98                    0.020
"arguments"             0.95                    0.051
:                       0.99                    0.010
{}                      0.93                    0.073
<im_end>                0.99                    0.010
────────────────────────────────────────────────────────
这一步的平均损失 =（0.010+0.030+…+0.010）/ 9 ≈ 0.035
```

（真实实现按 token 切分，"name"这类片段可能被拆成多个 token；上表做了简化。）

## 3 5 步怎么合成一条轨迹的损失

```text
第 1 步 JSON+im_end → 逐 token loss → 平均得到 a
第 2 步 JSON+im_end → 逐 token loss → 平均得到 b
第 3 步 …                       → 平均得到 c
第 4 步 …                       → 平均得到 d
第 5 步 …                       → 平均得到 e

这条轨迹的 loss =（a+b+c+d+e）/ 5
  等价说法：把 5 步里所有"参与 loss 的 token"放在一起取平均
  （不是把 5 步分别训练 5 次）
```

两个细节：

```text
· 用户话、observation 不参与 loss，但它们是上下文——
  模型是在"看到了工具回执"的前提下预测下一步动作的，这正是要学的能力。
· 一条轨迹的 assistant 步数不一样：500 条训练集里 T1 平均 5.1 步、
  T2 平均 8.9 步（最多）、T3 6.1、T4 4.0、T5 3.8 步（最少）；
  合计 2790 次 assistant 决策，每一次都被监督。
```

  合计 2790 次 assistant 决策，每一次都被监督。

```

## 4 8 条轨迹 → 一次参数更新（4 × 2）

```text
micro-batch 1：4 条轨迹（各自算完 loss）→ 前向 + 反向 → 得到梯度
micro-batch 2：再来 4 条             → 梯度继续累积（框架按累积步数平均）
────────────────────────────────────────────────────────────────
8 条轨迹的梯度合起来 → 优化器更新一次参数
  （只更新 LoRA 的 18,464,768 个参数；1.5B 基座冻结不动）
```

数字对账：

```text
500 条 / 8 = 62.5 → 每个 epoch 63 次更新（最后一次只有 4 条）
63 × 3 epoch = 189 次更新
checkpoint 也正好保存在 63 / 126 / 189 三个点
```

## 5 训练中到底"评测"了什么

```text
训练中：每个 epoch 结束，用 100 条验证轨迹算一次"验证 loss"
        （同样教师强制、同样只算 assistant token），
        用它选 checkpoint —— 这轮选的是 epoch3（验证 loss 0.0720）。
        训练过程中没有"每一步评测"。

训练后：200 条测试任务真正跑环境（最多 10 轮交互、C 标签判定 + D6 复核），
        得到 0% → 72.5% → 84.5% → 88.0% 的结果。
        这部分不参与参数更新，是独立评测。
```

## 7 一句话总结

```text
一条轨迹 = 一条训练样本；5 步 assistant 输出在这次前向里一起算交叉熵损失，
非 assistant 的 token 被 -100 屏蔽；
8 条轨迹（4×2）累积梯度后更新一次；3 个 epoch 共 189 次更新；
每个 epoch 只做一次验证 loss（选 checkpoint），
训练完之后的 200 条环境评测（C+D6）才是那个 88%。
```
