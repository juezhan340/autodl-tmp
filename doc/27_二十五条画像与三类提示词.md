# 二十五条画像与三类提示词

> 日期：2026-09-30
> 性质：审阅稿。定稿后再拷进 `new_demo/data_static/`。本稿不改 Python。
> 口径：`doc/26_闭区间主灯两档与任务指令配对.md`
> 结构与 19/24 相同：你要干什么 + 完整例子 + 本轮材料。
> 占位符：`{{persona}}` `{{s0}}` `{{intent}}` `{{task}}` `{{display_names}}` `{{user_request}}`
> D6 另用：`{{category}}` `{{finish}}` `{{turns}}`。T1/T2 不调 D6。

模型只输出该节规定内容：D2-1 一个 task JSON，D2-2 一句中文，D3 一个 `{accept, codes}`。不要前言，不要围栏，不要重复同一句结论。

```text
配对从 D2-1 的 intent 就开始，D2-2 按条说话，D3 按同样规则审

  condition.operator
        │
        ├─ eq   intent 写死目标     D2-2 精准话（关掉 / 调到二十二度 / 调到暗档 / 调到百分之三十）
        ├─ ge   intent 只写方向     D2-2 方向话（再暖一点 / 再湿一点），不念边界数字
        └─ le   intent 只写方向     D2-2 方向话（调低一点 / 暗一点），不念边界数字

  T2 有几条 condition 就拼几截，keep 再加「某某别动」
  T3 用户话一律感受向，可以不点设备；隐藏条件通常是 ge/le，主灯「太亮了」用 mode eq dim
  T4 probe 是精确非法数 → 用户话仍是精准话，听起来应当和 T1-eq 一样
  T5 只问状态

灯
  主灯   on + mode dim/bright，没有 level，没有 set_percentage
  台灯   on + level 0–100，set_percentage
  夜灯、廊灯、厨灯、浴灯、阳台灯   只有 on

闭区间中文
  ge    大于等于 / 至少 / 不低于 / 二十四度及以上
  le    小于等于 / 至多 / 不超过 / 二十六度及以下
  禁止用「以上」「以下」当开区间

观察
  T1 T2 T3 T5    required_observations = []
  T4             必须含被拒那台设备
```

D3 T1/T2 比 26 第 3 节更严：ge/le 配「调到二十六度」按配对错误拦掉（TARGET_NOT_COVERED）。T3 仍允许点「二十六度及以下」。审的时候看这一条能不能接受。

### T1  `T1_single_control.md`

```text
你要干什么：
你是数据辅助生成器。根据本轮画像和 s0，写一份 T1 单设备控制的 task JSON。
只改一台可控设备的一个字段。keep、required_observations 必须是空数组。outcome 必须是 completed。不要 answered，不要 facts。
operator 只能选一种，intent 必须和它同型：
  eq     intent 写死目标（关掉、调到二十二度、主灯调到暗档、台灯调到百分之三十）
  ge/le  只用于连续量（空调/热水器/冰箱/烤箱的 target，台灯/电视/加湿器的 level）
         中文语义是大于等于 / 小于等于
         intent 只写方向（调低一点、暗一点、再暖和一点），不要在 intent 里出现边界数字
         该条件在当前 s0 上必须尚未成立
主灯只能写 on 或 mode（dim/bright），不能写 level。台灯才能写 level。夜灯、廊灯、厨灯、浴灯、阳台灯只能写 on。
设备必须用 s0 里已有的 device_id。intent 必填，要体现画像。不要编造设备，不要写成拒绝，不要写用户那句口语。
只输出一个 JSON 对象。
```
