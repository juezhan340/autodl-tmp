# 复现原型与纲领的衔接：四个矛盾、改进空间与路线选择

| 项 | 内容 |
|---|---|
| 日期 | 2026-09-16 |
| 问题 | 复现 HomeFlow 的这条原型路线，能否一步步导入总纲领（三支柱）？论文上有什么矛盾、改进空间与方案 |
| 前置 | 同目录 1~9；`docs/09-论文最小复现方案-2026-09-16/` 全套（含 4B 实测与两篇论文分工） |
| 算力口径 | 单卡 RTX PRO 6000 96GB 可用，本机 8GB 只做开发与冒烟。**算力已不是主要矛盾** |

## 0. 结论先行

| 分类 | 内容 |
|---|---|
| 能导入 | 一条链：判定层（谓词 + 进度 + 审计）、训练基础设施、评测方法论 |
| 不能导入 | 世界本身：空间连通、时间演化、在线交互、真机迁移 |

论文上的矛盾集中在四处，算力不在其中：

| 矛盾 | 一句话 |
|---|---|
| 矛盾一 | 可验证奖励覆盖不到纲领的卖点（判定难度与卖点反向） |
| 矛盾二 | 离线回放器不是环境（契约不兼容） |
| 矛盾三 | 规则 agent 的数据来源撑不起六任务族 |
| 矛盾四 | 三套评测口径并存，单篇容易虚胖 |

算力到位之后，剩下的是设计与工程问题，而且比显存难得多。

## 1. 迁移表：哪些能搬，哪些要重做

| 复现原型的产物 | 对应纲领的哪里 | 判断 | 交接方式 |
|---|---|---|---|
| 谓词目标 + 进度 m_t | 支柱二 可验证奖励 | 可直接搬 | 判定层的接口原样复用 |
| 审计四类拒绝 | 支柱二 L3 安全合法性 | 可直接搬 | 审计器与错误码表 |
| 规则 agent | 支柱二 L1 数据来源 | 部分可用（只够 T2） | 降级为可解性 oracle |
| 环境判定 + 五模型基线 | 评测口径 | 可直接搬 | 含 24.1% 地板这个对照 |
| SFT/GRPO 工程经验 | 支柱二 训练基础设施 | 可直接搬 | 显存账、日志、噪声底方法论 |
| 单轮离线回放 | 支柱二的 step 契约 | 不能用 | 只作判定层参考，环境另起 |
| 1 房间 4 设备 | 支柱一 T1 空间连通 | 没有 | 需要在沙盒侧新建 |
| 无时间推进 | 支柱一 T4 与 T1b | 没有 | 依赖时间核，见同目录 9 |
| JSON 六工具 | 支柱三 同语义 MCP | 没有 | 需要 ToolSpec 与双后端，见同目录 8 |
| 100 条单路径轨迹 | 六任务族覆盖 | 没有 | 需要可验证数据飞轮 |

一句话：**复现线交付的是"判定与评测"，不是"世界"。**

## 2. 矛盾一：可验证奖励覆盖不到纲领的卖点

纲领的差异化在 T1（拓扑因果）与 T5（主动服务时机），而这两类恰恰最难写成谓词。逐族过一遍：

| 任务族 | 能不能写成状态谓词 | 缺口 |
|---|---|---|
| T1a 空间 grounding | 能（终态） | 无 |
| T1b 连通传播 | 能（终态 + 时间） | 必须有时间核，否则验证不了"传过去了没有" |
| T1c 拓扑因果 | 能（终态） | 差异靠实验设计（同设备不同连通），不是判定 |
| T1d 空间副作用 | 能（保持类谓词） | 需要"未涉及房间不许变"的系统化约束 |
| T2 指令执行 | 能 | 无 |
| T3 模糊/省略/指代 | 一半 | "能推断出目标"可判；**"该不该澄清"判不了** |
| T4 时间调度 | 能（终态 + deadline） | 需要 tick 与事件调度 |
| T5 记忆/个性化 | 一半 | "照着偏好做了没有"可判；**"该不该主动做"判不了** |
| T6 环境感知 | 只能间接 | 查询动作本身无奖励，只能靠效率项约束 |

论文上的后果很直接：如果训练收益全部来自"能写成谓词的那一半"，审稿人会问——**你删掉的正好是论文声称最难的部分，这算不算用简化换分数？** HomeFlow 的应对方式是干脆不碰（把 TC4/TC7 移出训练与评测），SMH-Bench 的应对方式是引入裁判并对裁判做人工盲审。

可行的写法是三档判定，训练只用第一档：

    第一档  状态谓词        终态、进度、保持类约束        训练与评测都用，零噪声
    第二档  行为标签        该澄清 / 该拒绝 / 该先查询      给任务预标"正确行为"，结构化匹配
    第三档  裁判 + 人工抽样  澄清是否恰当、答案是否事实正确  只用于评测，且必须报噪声

## 3. 矛盾二：离线回放器不是环境

复现原型的运行方式是"一次给完上下文 → 模型写整段动作 → 环境回放 → 算分"。纲领要的环境是"决策点式交互"。两者在四个语义上不兼容：

| 语义 | 回放器（现状） | 环境（纲领需要） |
|---|---|---|
| 推进权 | 谁都不推进，事后重跑 | 只有 step 推进，且由训练循环持有 |
| 决策点 | 没有，一次写完 | 读类动作不推进；改状态推进到后果可见；等待推进到指定时刻 |
| 观测边界 | 模型看不到中间观测 | 每步只回直接执行结果，强制主动查询 |
| 回合终止 | 模型停止生成即结束 | 目标达成 / 失败 / 超步数，由环境判定 |

后果：纲领里 T1b 的"效果沿连通边传播"和 T4 的"洗碗机洗完开厨房灯"都做不了——这两件事都依赖时间推进与在线观测。

处理办法是把 homeflow_min 的角色降下来：**它是判定层的参考实现，不是沙盒的种子。** 环境按同目录 4 与 9 的步骤另起（同步内核 → Gym 外壳 → 条件判定 → MCP），两者共享的只是谓词、进度、审计这套数据结构。

## 4. 矛盾三：规则 agent 撑不起六任务族的数据

规则 agent 只在 T2 这一类上够用。它的三个天花板：

    只会照抄谓词    目标写 temp <= 24 就永远设 24，不做"要不要动"的判断
    只会单条路径    同一个目标永远给同一条最短序列（实测：100 条轨迹只有 28 条互异）
    生成不了行为    造不出"该澄清""该拒绝""该等一等"这类正确行为

纲领需要的训练数据是六任务族的，其中 T3/T4/T5 恰恰都需要上面这三样。所以数据来源必须升级成"生成 → 环境验证 → 筛选"的飞轮，也就是 HomeFlow 里 MCTS-Flow 那个位置。它和规则 agent 的分工应该是：

    规则 agent    可解性 oracle（任务必须它也能解）+ 下界参照 + T2 的批量数据
    生成式采样    强模型/树搜索产出候选轨迹 → 环境跑一遍 → 只留达标的
    筛选记录      合成成功率、轨迹多样性、每族覆盖率，三个数都要报

这里有一条容易被忽略的论文细节：HomeFlow 为了让"可验证"这个卖点站得住，明确做了**等样本量对照**——角色扮演基线用同样数量的样本训练，结果仍然更差。我们也必须有这一条，否则审稿人会把增益归给"你数据更多"。

## 5. 矛盾四：三套评测口径并存

三根支柱各有自己的评价标准，混在一篇里最容易虚胖：

    benchmark    成功率、非法动作率、泛化（未见拓扑）
    训练         SFT vs SFT+RL 的消融、奖励设计消融
    迁移         零适配 / schema 适配 / 少样本适配 下的成功率保持、调用数、修改量

风险有三层。一是三套口径的样本量、判定方式、随机性各不相同，结论之间会互相打架；二是非执行类任务必须挂裁判，裁判噪声会渗进 benchmark 与迁移两处结论（我们实测过：同权重换采样种子，裁判分差 0.18）；三是实验规模一旦按三支柱铺开，单篇的实验量会变成三篇的量。

处理办法是**一张实验矩阵**，而不是三套实验：

    行    六个任务族（T1~T6）
    列    三种配置（prompt 基线 / SFT / SFT+RL）× 两个后端（沙盒 / HA）
    格内  成功率 + 非法动作率 + 工具调用数（客观指标优先）
    附列  裁判分只在非执行类任务上出现，且必须附噪声量级

## 6. 算力：降级为配置问题，但边界仍要说清

    96GB 单卡解锁的
        4B / 8B 的全参 SFT（bf16 下 8B 全参训练约需 70GB 上下，单卡可容）
        LoRA / DPO / GRPO / RLVE 全套训练
        bf16 推理与并行 rollout，不再依赖 4-bit 量化
        MCTS 式树搜索量产轨迹（并行多条模拟，显存不再是瓶颈）
        每轮实验的成本从"过夜"降到"几小时"

    仍然没解锁的
        真实家庭数据（智能家居没有公开大规模真机轨迹）
        真机的空间拓扑（HA 的 area/连通关系依赖用户配置）
        人的真实偏好与长期行为
        "主动服务做得对不对"这类判定——这是设计问题，算力解决不了

一句话：**算力解决"跑得动"，解决不了"判得准"和"测得真"。** 前面四个矛盾一个都没被它消掉。

## 7. 复现线还能改进的六处

    一  把回放器 Gym 化（哪怕仍是单房间）
       reset(seed) / step(action) / terminated / truncated / 并行实例 / 固定步长。
       改完之后评估与训练都换成标准契约，搬去纲领沙盒时不用重写。

    二  目标从终态扩到两段式
       终态谓词 + deadline tick（"20 分钟内到 24℃"）。这是 T4 的最小形态，
       现有判定层加一个时间条件即可。

    三  加一维空间
       房间邻接表 + 设备效果作用域，让"厨房没有空调、开门后客厅的冷气能过来"
       这类最小 T1 任务出现，哪怕只有一个门、一次传播。

    四  判定分三档落地
       谓词 / 行为标签 / 裁判，训练只用第一档，评测才允许后两档。

    五  数据从单路径扩到多路径
       同一目标生成 5~10 条互不相同的合法轨迹（随机取值、打乱顺序、换查询策略），
       先把轨迹多样性从 28/100 拉到接近 100/100。

    六  把噪声方法论固化进模板
       先量噪声再看差距、客观指标优先、同配置至少两次——这套已经成熟，
       直接写进纲领的实验规范。

## 8. 三条路线

    A  就地升级
       在 homeflow_min 上加时间与空间的最小版本，再 Gym 化。
       成本中，几天出活；但单房间假设撑不住 T1，最终仍要换沙盒。
       适合"想尽快看到一条端到端链路"的情况。

    B  直接转正
       复现封版，全力做 SimuHome 的 Gym 化与空间连通（同目录 5/8/9 的改造顺序）。
       成本高，风险是沙盒改造期间没有能跑的产物，进展不可见。

    C  双轨（推荐）
       复现线上 96GB 卡做完"毕业标准"里的三件事即封版；
       同时按 9 号文档的四步推沙盒线。
       复现线交付判定层与训练基础设施，沙盒线交付世界。

## 9. 复现线的毕业标准（升级版）

算力放开之后，这三条都变成几小时级的事，达标就停，不再加数据、不再调参：

    1  在 4B 底座上跑通 SFT 冷启动
       验收：格式合法率从 0 提到 90% 以上；非法动作率显著下降
    2  跑通一次奖励消融
       验收：复合奖励 vs 只给终局奖励，两次同种子运行方向一致
    3  评测模板沉淀
       验收：客观指标 + 噪声底 + 三档判定的报告模板可以直接套到纲领实验上

沙盒线的四步与验收标准沿用同目录 4 与 9：

    第 0 步  主循环抽成同步 world.advance_until(...)，把推进权收回环境
    第 1 步  SpaceHomeGymEnv：reset(seed) / step 五元组 / 每 worker 一个世界
    第 2 步  ConditionChecker：终态谓词 + 空间副作用 + deadline 三类条件
    第 3 步  同一份 ToolSpec 注册成 MCP，沙盒与 HA 各实现一份
    验收     三房间连通场景，1,000 条 SFT 轨迹 + 小规模 RLVE；
             同一策略在 env.step 与 MCP 两条路径上行为一致

## 10. 交接面：复现线交给纲领什么

| 交接物 | 形态 | 交给谁 |
|---|---|---|
| 谓词与进度判定 | `home_predicate` 那套数据结构 + 求值函数 | 支柱二 L2/L3 的条件判定 |
| 审计与错误码 | 四类拒绝 + 返回文本 | 支柱二 L3、支柱三 MCP 错误语义 |
| 评测报告模板 | 成功率/完成率/格式率/非法动作/工具调用数 | 三支柱共用的实验矩阵 |
| 噪声底方法 | 同权重换种子、客观指标优先 | 实验规范 |
| 训练工程参数 | 显存账、日志落盘、检查点 | 支柱二在 96GB 卡上的训练脚本 |

不复用的部分也要写清楚：单轮回放循环、规则 agent 生成的 100 条数据、1 房间布局，这三样留在复现线，不进纲领。

## 11. 还不能声称的

    ✗ 不能说复现原型验证了纲领的任何一根支柱 —— 它验证的是"环境判定能驱动学习"
    ✗ 不能把复现的 64M 数字写进 UbiComp 论文当结果 —— 那是复现，不是贡献
    ✗ 不能说"可验证奖励可以覆盖全部任务族" —— T3/T5 各有一半判不了
    ✗ 不能说"有 96GB 卡就能做出论文级实验" —— 数据来源与判定协议才是瓶颈

## 12. 收束

复现线的价值在于把"可验证奖励"这条链练熟，它是支柱二的地基；但纲领的论文增量在**三根支柱合起来那部分**——空间连通、时间演化、同语义迁移——复现线一样都提供不了。算力到位之后，这一点更清楚：剩下的四个矛盾全是设计问题，其中"判定难度与卖点反向"最要紧，因为它直接决定论文能不能自圆其说。
