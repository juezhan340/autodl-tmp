# 多任务训练调度设计（T1–T7：SFT + RL）

> 定位：这是大任务里的一个训练模块。不讲创新点、不谈审稿人，只回答"训练怎么走"。
> 输入：每类 200 条成功轨迹（合计 1000 条）+ 每类评测集；输出：一套可直接实现的调度方案。
> 依据：arXiv 检索（课程学习 / 数据配比 / 调度 / 遗忘，共 16 个查询、30 余篇论文），每个决策标注出处。

## 0 设计目标

```text
目标 1  不偏科：最差类的指标要达标，而不是只看平均
目标 2  不遗忘：某类训好了之后，后续训练不许把它拉回退

约束
  数据量有限（每类 200 条 ×5 类，未来 7 类）
  训练要一轮走完，不做"回头大重训"
```

## 1 从文献里提炼的四条设计原则

```text
① 配比不能是常数，要随训练进程动
   依据：ODM 2312.02406（在线调配比）、HDS 2606.24133（多目标调度）、
        ADS 2606.22305（自适应分布替代均匀采样）
   → 做法：每 K 步按各类指标重算一次采样权重

② 采样要盯"当前还不会、但学得动"的样本
   依据：AdaRFT 2504.05520（奖励信号定难度）、GACL 2508.02988（性能监控）、
        DISCO 2505.15074（不确定性高的样本优先）、DAPO 2503.14476（丢弃无梯度组）
   → 做法：RL 阶段优先 pass rate 在 0.2–0.8 的样本；全对/全错组降权

③ 混合训练为主，串行只作退路
   依据：2308.08747（LLM 持续微调确实遗忘）、SSR 2403.01244（回放有效）、
        Nemotron-Cascade 2512.13607（域级串行可以做，但要专门设计）
   → 做法：默认全程混合打散；若算力受限必须串行，按 cascade 方案配回放

④ 每类设置"保底配额"，训好了也要留少量样本
   依据：SSR 2403.01244、AdaCuRL 2511.09478（历史回访）、
        Entropy Pacing 2607.07178（多任务 RL 的节奏错配）
   → 做法：任何一类的采样占比不得低于 ε（先取 5%–10%）
```

## 2 训练主流程

```text
阶段 0  准备
  把每类 200 条轨迹切出 80% 训练池 / 20% dev（dev 只喂调度器，不进训练）
  final 评测集单独留出，调度全程不许看

阶段 1  SFT：混合起步
  全部类别打散，一个训练账本，不做 T1→T2→…→T5 的顺序课程
  初始配比：均匀 1/C（先不预置任何偏好，交给阶段 2 自动调）
  每 K 步存 checkpoint，并在 dev 上评一次每类成功率 s_c

阶段 2  闭环调度（SFT 中后期开始启用）
  平滑：  ŝ_c ← 0.5·s_c + 0.5·ŝ_c（防单次评测噪声）
  权重：  w_c ← w_c · exp(η · (1 − ŝ_c))，η 先取 0.5
  夹逼：  w_c 限在 [ε, 3/C]，ε = 5%～10%；再归一到和为 1
  节奏：  每 K 步更新一次，且新旧权重按 0.5 混合过渡（防震荡）
  直觉：  弱类权重涨、强类权重回落，但强类永远不低于 ε

阶段 3  RL / GRPO（SFT 收敛后）
  采样：沿用阶段 2 的权重 w_c；每任务一个 group（G≈8 条 rollout）
  奖励：环境自动判定（C 标签；模糊类加 D6），无需人工标注
  过滤：group 内全对/全错 → 无梯度，降权或丢弃（DAPO 动态采样）
  难度：pass rate 落在 0.2–0.8 的样本优先（AdaRFT / DISCO 的思路）
  观察：每类的策略熵/回复长度，若易类过早收敛（熵过低），
        降其权重、把采样温度补给难类（Entropy Pacing 2607.07178）
  可选：若出现"主类吃满"的不平衡，叠加 DISCO 的域感知奖励缩放

阶段 4  验收
  worst-case：min_c 成功率要达标（而不是只看平均）
  遗忘量：每个类训练前后 dev 指标差 Δ_c，要求不显著为负
  样本效率：达标用的总样本数，与均匀/顺序两组对照
```

## 3 参数起点表（先按这个跑，再调）

```text
参数                    起点值          调整方向
──────────────────────────────────────────────────────────────
初始配比 w_c            均匀 1/C        不动，让闭环自己调
更新间隔 K              每 1/10 训练量  数据少时改成每 N step 一次
调节力度 η              0.5             震荡就调小，迟钝就调大
EMA 系数                0.5             评测噪声大就调小（更平滑）
回放下限 ε              5%              遗忘明显就升到 10%–20%
权重上限                3/C             弱类仍不动就放宽
GRPO group 大小 G       8               显存不够降到 4
难度带                  0.2–0.8         任务太易/太难可移动两端
```

## 4 与现有数据、评测的对接

```text
数据         quota200_20261004_v2 已带 T1–T5 标签，直接切训练/dev
调度信号     C-1..C-4 自动判定 + D6（模糊类）就是天然的 s_c，
             不需要新造评测；每次 checkpoint 顺带跑一遍 per-class dev 即可
调度输出     一张采样权重表（json：{task_type: weight}），
             训练脚本按权重采样；实现代价 = 一个几十行的采样器
接口边界     调度器只改"每类拿多少样本"，不改任务内容、不改评测口径
```

## 5 先做的最小验证实验

```text
规模：小模型（1.5B LoRA 起步）跑 SFT，三组对照
  A 均匀混合        基线
  B 顺序 T1→T5      复现漂移/遗忘
  C 闭环调度        本方案（阶段 2 全开）

看两个数
  worst-case 类成功率（C 应 ≥ A 且 ≥ B）
  遗忘量 Δ_c（B 应明显为负，C 应接近 0）

通过后再上阶段 3 的 GRPO；GRPO 上重点复看：
  全对/全错组占比、pass rate 分布、每类策略熵
```
