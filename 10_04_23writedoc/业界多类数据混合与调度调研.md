# 业界怎么把多类数据混合、调度、防遗忘：调研

> 问题：大数据集/小数据集分成很多类时，业界训练时怎么混合、怎么调度、怎么处理？
> 范围：大厂公开报告（GPT-3、Llama 3、OLMo 2、Tülu 3 等）+ 相关文献 + 成熟开源方案
> 结论均可溯源，链接见文末

## 0 一屏：先给三个直接答案

```text
答案 1：这些东西在业界叫什么

  数据层面         data mixing / data blending（数据混合）
                   sampling weights / proportions（采样权重/配比）
                   domain reweighting（域重加权）
                   upsampling（小数据高质量集上采样）

  训练阶段层面     staged training / multi-stage training（分阶段训练）
                   mid-training（中期训练）
                   annealing / late-stage curriculum（退火/后段课程）
                   —— 这就是"课程学习"在业界的落地形态：
                      报告里几乎不写 curriculum learning，
                      写的是"分几个阶段、每阶段换什么 mix"

  RL / 防遗忘      dynamic sampling（动态采样，DAPO）
                   replay / rehearsal / replay ratio（回放比例）
                   online data mixing（在线配比，研究前沿）

答案 2：业界主流怎么混合

  一个套路，四个动作：
  ① 拿小模型做配比实验（缩放律/消融）→ 定几个候选配比
  ② 训练大模型时用固定权重采样（不按数据量比例；高质量的过采）
  ③ 训练分阶段：主体阶段一个 mix，后段退火/中期换"高质量上采样"的新 mix
  ④ 小数据集靠"上采样 + 重复轮数上限"存活，低质大数据往下降权

答案 3：你想的"按指标闭环调配比"在业界什么位置

  确实有人这么做，而且 2025–2026 年越来越热：
    ODM（在线数据混合）、ADS（自适应数据调度）、
    MoDoMoDo（多域 RL 配比优化）、RoD（按遗忘动态分配回放）
  但在公开的大厂报告里，主流仍是"离线定配比 + 分阶段固定 mix"，
  在线闭环调度更多出现在论文和前沿团队，还没有成为标准公开配方。
```

## 1 术语地图：每个词是谁的、什么意思

```text
术语                          场景          含义                              谁在用
────────────────────────────────────────────────────────────────────────────────────────
data mixing / blending        预训练/SFT    多数据源按权重混合成一个训练分布    全行业
sampling weights              预训练        每个源的采样概率（≠数据量比例）     GPT-3 起的标配
proportions                   通用          同上，可在配置里写 0.4/0.1/0.5      工具通用叫法
upsampling / repeat factor    预训练        小/高质量集被重复抽，epoch 数抬高    GPT-3、Llama 3
epochs per source             预训练        训练中每个源被翻到几遍               GPT-3 表格列名
data ablation                 全阶段        去掉/调换一个数据块看指标变化        Tülu 3 等
scaling-law experiment        预训练        小模型配比实验外推大模型效果         Llama 3
staged / multi-stage training 预训练/SFT    分阶段训练，每阶段换 mix/目标        Llama 3、OLMo 2、Tülu 3
mid-training                  预训练后期    高质量中训阶段（OLMo 2 叫 Dolmino）  AI2
annealing / late-stage        预训练最后段   LR 退火到 0 时用高质上采样 mix      Llama 3
curriculum learning           学术/工具     先易后难、动态难度                   DeepSpeed 实现、RL 研究
difficulty filtering          数据准备      按难度分桶/过滤样本                  各数据集管线
dynamic sampling              多任务 RL     丢弃/降权"全对/全错"的无梯度组       DAPO、verl 生态
replay / rehearsal            防遗忘        混回旧数据，比例=replay ratio       持续训练、RoD
online data mixing            研究前沿      训练中在线调配比                     ODM/HDS/ADS
```

一个关键澄清：

```text
学术里的 "curriculum learning" 在业界不是直接按名字落地的。
业界把它拆成了三个可操作的工程概念：
  分阶段（stages）+ 每阶段配比（mix）+ 后段退火上采样（annealing/upsampling）
你设想里的"强类减样本、弱类加样本"，在业界语境里对应的是两个词：
  reweighting（重加权，静态）与 online scheduling（在线调度，动态）
```

## 2 大厂是怎么做的（逐个案例）

```text
① GPT-3（2020，OpenAI）
   做法：给每个数据源定固定权重（训练时采样比例），
        明确"刻意不按数据量比例采样"
   例子：Common Crawl 410B token 只占 60% 训练权重；
        高质量、小体量的数据集被采样 2–3 个 epoch，
        又大又杂的 Common Crawl 训练 300B token 时还没过完 1 遍
   要点：小数据怕被淹没 → 上采样；大而杂 → 降权
   出处：GPT-3 论文 §2.2 与数据表（arXiv:2005.14165）

② Llama 3（2024，Meta）
   做法（配比怎么定）：知识分类器 + 缩放律实验——
        先在小模型上试多个候选 mix，用结果预测大模型表现，
        反复迭代选下一版候选 mix
   做法（训练怎么调度）：分阶段。最后有一段"退火"：
        LR 线性退到 0、约 40B token，这段用"高质量数据上采样"的 mix；
        并专门用"退火实验"来评估小体量领域数据值不值得加
   例子：数学数据上采样；训练后期加更新鲜的网页数据提高知识截止；
        后段发现质量低的子集降采样
   出处：Llama 3 论文 §3、§4（arXiv:2407.21783）

③ OLMo 2（2025，AI2）
   做法：两段式训练，每段有自己的 mix——
        预训练用 OLMo 2 Mix 1124（以网页为主），
        之后"mid-training（中训）"换成 Dolmino Mix 1124：
        DCLM 高质网页 top 7%、FineWeb 高质量、合成数学数据等
   效果：官方称这种"late-stage curriculum training（后期课程）"
        显著提升一系列下游基准
   要点：不是全程一个配比；"换 mix"本身就是提升手段
   出处：OLMo 2 论文 §2–§4（arXiv:2501.00656）

④ Tülu 3（2025，AI2，后训练方向最系统的公开配方）
   做法（SFT 配比）：先按技能建"技能特化配比"分别训小版本，
        挑各自最好的混合，再合并成候选总配比；
        然后做多轮 SFT 消融实验（去掉某个数据块看影响）定稿
   做法（偏好 + RL）：DPO 配比同样靠消融定；
        最后加 RLVR 阶段（可验证奖励的 RL），任务混合
        数学 + 精确指令遵循等；设计时故意不看不公开测试集
   要点：配比不是拍脑袋，是"小步实验 + 迭代合并"出来的
   出处：Tülu 3 论文（arXiv:2411.15124）
```

## 3 分场景的通用配方（预训练 / SFT / RL / 防遗忘）

```text
预训练（最多公开资料的场景）
  ① 配比搜索：小模型跑候选 mix（缩放律/回归/代理模型）→ 选优
     文献：DoReMi 2305.10429（Group DRO 定域权重）
           RegMix 2407.01492（把配比选择做成回归预测）
           数据混合定律 2403.16952（性能-配比可预测）
  ② 固定权重训练：按权重采样，小数据上采样（注意 epoch 上限）
  ③ 后段调度：annealing / mid-training 换高质量 mix（Llama 3、OLMo 2）
  ④ 在线调度（新趋势）：训练中动态调配比
     ODM 2312.02406、HDS 2606.24133、ADS 2606.22305

SFT（指令微调，多任务/多技能混合）
  ① 主流：配比消融（Tülu 3 式）；技能配比分头调再合并
  ② 动态权重（较新）：按训练状态调整各数据集权重
     MoE 指令微调动态配比 2406.11256；SMART 2403.08370（子模函数打分）
  ③ 工程上：一个 batch 里按概率混不同数据集（工具都支持，见第 5 节）

RL / RLVR（可验证奖励的多任务后训练）
  ① 多域配比优化：MoDoMoDo 2505.24871——
     学一个"配比 → 结果"的预测器，再搜最优配比；
     比均匀配比在 OOD 上平均 +5.24%
  ② 跨域影响实证：2507.17512——单域训练、组合训练的互相促进/冲突
     都实测过；结论：域之间不是简单相加，配比要实测
  ③ 动态采样：DAPO 2503.14476——全对/全错的组没有梯度，丢弃或降权
  ④ 域级串行：Nemotron-Cascade 2512.13607——按域串行 RL 也能不掉点，
     但需要专门设计（与你"怕顺序遗忘"直接相关）
  ⑤ 域不平衡防御：DISCO 2505.15074——GRPO 上做域感知/难度感知奖励缩放

防遗忘（持续训练场景）
  ① 业界基线：固定 replay ratio（混回旧数据的一个固定比例），
     比例靠实验调——RoD 论文原话就是对比"tuned fixed-replay baselines"
  ② 常见现象：持续预训练早期有"stability gap"（指标先掉后恢复）
     文献：2406.14833
  ③ 新研究：Replay on Demand 2609.40089——
     按"模型的实际遗忘量"动态分配回放：适应样本按剩余学习潜力、
     回放样本按已观察到的遗忘量，共享同一个训练预算；
     形成在线课程，不用预设回放比例
     这基本就是你设想的学术版（场景是持续预训练）
  ④ 回放数据来源：旧数据/合成回放（SSR 2403.01244）
```

## 4 你想的那种"按指标闭环调配比"，处在什么位置

```text
定位：在线调度（online scheduling）里的"指标驱动"一派，
      不属于业界公开配方的主流，但 2025–2026 研究热度明显上升。

代表人物（都把"按模型状态动态分配"做出来了）：
  RoD 2609.40089      按"实际遗忘量"动态分配回放配额（持续预训练）
  ADS 2606.22305      按语义簇 + policy-boundary 样本自适应采样（RL 后训练）
  MoDoMoDo 2505.24871 多域 RLVR 配比预测 + 优化（多模态）
  ODM 2312.02406      预训练在线混合（早期代表作）
  HDS 2606.24133      多目标 RL 做数据调度（预训练）
  DISCO 2505.15074    GRPO 域不平衡的奖励侧修正

与业界主流的差距（实话）：
  公开的大厂配方（GPT-3/Llama 3/OLMo 2/Tülu 3）都是
  "离线定配比 + 分阶段固定 mix + 后段退火"，没有一家的报告
  承认在生产预训练里跑"每 K 步按验证指标重算配比"。
  原因很现实：评测贵、训练稳、复现难。

你们的场景反而适合在线的三个条件：
  ① 评测便宜：C-1..C-4 自动判定 + D6，每次 checkpoint 都能出 per-class 指标
  ② 数据小：1000 条级别，重采样/重混成本几乎为零
  ③ 类就 5–7 个：配比空间小，稳定性比预训练好控制
  → 这正是"把研究前沿做法用在小规模场景"的合理位置
```

## 5 成熟开源方案盘点（全部核对过官方文档/源码）

```text
① 预训练 / 大规模混合

  Megatron-LM（NVIDIA）— BlendedDataset
    混合怎么表达：每个数据前缀带权重（blend / blend_per_split 配置），
                  数据集构建器按权重把多个来源合成一个训练集
    源码：megatron/core/datasets/blended_megatron_dataset_builder.py
    评价：大厂外最主流的预训练框架，加权混合是内置能力

  MosaicML Streaming（Composer 生态）
    混合怎么表达：Stream(remote=..., proportion=0.4)——
                  多个 Stream 各写一个 proportion，按比例混合
    官方 README 示例：
      Stream(remote='s3://datasets/c4', proportion=0.4),
      Stream(remote='s3://datasets/github', proportion=0.1),
      Stream(remote='gcs://datasets/my_internal', proportion=0.5)
    评价：流式数据集，多源按比例混；改比例=改配置

  HuggingFace datasets
    混合怎么表达：interleave_datasets([d1,d2,d3],
                   probabilities=[0.3,0.5,0.2], seed=...)
    两种收尾策略：
      stopping_strategy="all_exhausted"                    → 过采样
      stopping_strategy="all_exhausted_without_replacement" → 每样本恰好一次
    评价：最轻量的通用做法，训练脚本几行就能接

② SFT / 指令微调

  LLaMA-Factory（国内最常用）
    mix_strategy: concat / interleave_under / interleave_over / interleave_once
    interleave_probs: 每个数据集的概率（个数必须与数据集数一致）
    源码：src/llamafactory/hparams/data_args.py
    评价：写进配置即用的多数据集概率混合

  HF 生态：同一套 interleave_datasets 可直接用于 SFT 数据混合

③ 课程学习（少见的成品实现）

  DeepSpeed Data Efficiency
    内置 curriculum learning（引 Bengio 2009）：
      先做数据难度分析（用户提供难度度量，ds_analyze_*.sh 脚本），
      再按调度曲线先易后难训练
    教程：deepspeed.ai/tutorials/data-efficiency
    评价：开源里少见的"课程学习"开箱实现，面向预训练

④ RL / 多任务

  verl（字节）：GRPO / DAPO 等算法生态；
    DAPO 动态采样（全对/全错组无梯度，丢弃或降权）在其 recipes 中
  行业现状：RL 框架普遍支持"多数据集列表 + 采样器"，
    但"自动按指标调采样权重"大多要自己写 sampler
    （想抄作业看 MoDoMoDo 的配比预测器）
```
