# 动态训练与课程学习：命名、对照与创新点分析

> 场景：T1–T5（可能扩到 T7）智能家居多任务 post-training（SFT + GRPO 式 RL）
> 目的：给"混合打散 + 按类指标动态调配比 + 少量回放防遗忘"这套设想定性、命名、找对标、评估能不能写进论文
> 检索：arXiv 全文检索两轮共 16 个查询、逐条核对论文摘要；结论均可溯源

## 0 先把你要解决的问题说清楚

```text
问题 1  机械等量配比（每类 50 / 500 / 5000 条）→ 偏科
        T2 训得够、T4 训不动；总量上去了，最差类没上去

问题 2  顺序分阶段训练（先 T1 再 T2 再 T3 …）→ 漂移 / 灾难性遗忘
        后学的把先学的覆盖掉，评测集上老任务回退

你的设想
  第一步   T1–T5 混合打散，从头就不给"顺序覆盖"的机会
  第二步   按类指标闭环：强类减样本、弱类加样本
  第三步   强类保留少量"保鲜"样本（回放），防止新训练阶段把它冲掉
```

这三步在学术上分别有名字，但"三步合起来"目前没有单一现成名词——这就是你问"应该叫什么"的答案来源。

## 2 "动态训练"这个名字能用吗？三个候选的利弊

```text
候选名                          优点                     风险
────────────────────────────────────────────────────────────────────────────
动态训练 Dynamic Training       顺口                     太泛，检索无指向，审稿人无感；不建议单独用
课程学习 Curriculum Learning    正统、有 2009 年的根基    容易被认为"旧瓶装新酒"，
                                                         必须强调闭环指标 + 回放
自适应数据调度                 准确、与 2026 年新工作接轨 名字较新，需用 ADS/DISCO 界定差异
Adaptive Data Scheduling
```

建议：大伞挂"课程学习 / 数据调度"，定语写清三个限定词——

```text
Performance-Guided Curriculum Scheduling
  with Forgetting-Aware Rehearsal
  for Multi-Task Agentic Post-Training

中文：面向多任务智能体后训练的
      "指标闭环调度 + 防遗忘回放"课程方法
```

避免两个坑：只叫课程学习 → 显得没新意；只叫动态训练 → 检索不到、无法与任何工作对话。

## 3 最接近的既有工作（必须引、必须划清边界）

```text
① ADS（arXiv:2606.22305，2026）
   Learning at the Right Pace: Adaptive Data Scheduling Improves LLM RL
   最接近：RL post-training 里用自适应分布替代均匀采样，
   按"语义簇 + policy-boundary 样本"调度。
   差异：它按语义簇和策略边界，不按任务类别指标；没有显式回放防遗忘。

② DISCO（arXiv:2505.15074，2025）
   Domain- and Difficulty-Aware RL on Imbalanced Data（GRPO 变体）
   最接近：多域不平衡 + GRPO；域感知奖励缩放 + 难度感知缩放。
   差异：它改"奖励权重"（优化侧），你改"采样配比"（数据侧）；
   它不做跨类闭环检测，也没有保鲜回放。

③ AdaCuRL（arXiv:2511.09478，2025）
   Adaptive Curriculum RL with Invalid Sample Mitigation and Historical Revisiting
   最接近：难度课程 + 历史样本回访（含回放成分）。
   差异：面向推理题目难度，不是多任务类别配比。

④ Nemotron-Cascade（arXiv:2512.13607，2025）
   域级串行 RL（cascaded domain-wise RL），论证串行不落后于混合。
   它是你"顺序训练会遗忘"论断的反例/对照组，必须读。

⑤ HDS 2606.24133 / ODM 2312.02406 / D3 2605.31164
   在线配比调度 / 动态数据调度，但都面向预训练，不是指令后训练。

⑥ 遗忘侧：2308.08747（LLM 持续微调遗忘实证）、SSR 2403.01244（自合成回放）
   提供"遗忘测量"与"回放有效"的引用依据。
```

判断：**单点都有主，组合没有被完全做掉。** 最接近的是 ADS 和 DISCO，两者都缺"类级指标闭环"和"回放约束"这两个元件。缝隙真实存在，但不宽——适合作为"小而实"的创新点。

## 4 怎么从"工程技巧"升级成"方法贡献"

审稿人最可能的质疑是"这不就是调采样比例吗"。要把调度本身形式化，站进在线优化的框架：

```text
记号
  c ∈ {1..C}   任务类别（T1–T5 / T7）
  s_c(t)       第 t 轮评测中类别 c 的指标（成功率 / 最差子项通过率）
  w_c(t)       类别 c 的采样权重

调度律（候选一：乘性调整）
  w_c(t+1) ∝ w_c(t) · exp( η · (1 − s_c(t)) )
  直觉：指标低 → 权重涨得快；指标高 → 权重自然回落

防遗忘约束（区别于 ADS 的关键）
  p_c ≥ ε_c      已掌握类别保留最小采样比例
  可加遗忘惩罚：若 s_c 比历史最好值回退，ε_c 自动上调

完整目标（可写进论文）
  max  min_c s_c(T)          （最差类最优，而不是平均类最优）
  s.t. 采样预算 B、遗忘界 |s_c(T) − best_c| ≤ δ_c
```

这样写法下，它不再是一个调参 trick，而是"worst-case 类指标最大化 + 遗忘约束下的采样调度"——一个有约束的在线优化问题。可以借多臂老虎机（每类一条臂、奖励=验证提升）或 DRO 的语言来写，也为"扩到 T6/T7 时调度器自动适配"留出叙事空间。

## 5 对照实验怎么设计（决定它能不能站住）

```text
必做对照
  1 均匀配比                机械 baseline
  2 静态最优配比            离线搜索（RegMix 风格），证明动态优于静态调好
  3 顺序训练 T1→T5          复现遗忘，量化 forgetting gap
  4 动态配比但无回放         消融 ε_c，证明回放不是装饰
  5 随机课程 / 逆难度课程     证明调度信号有效，不是随便打乱都行
  6 完整方法                闭环 + 回放下限

可选加分
  7 与 DISCO 的奖励缩放叠加   数据侧 + 奖励侧组合
  8 与 PCGrad / GradNorm 叠加 梯度平衡 × 数据调度，说明正交性

指标
  每类成功率、worst-case 类成功率、平均成功率
  遗忘量 Δ_c = s_c(训练后) − s_c(训练前)，越低越好
  样本效率：达到目标 worst-case 指标所需训练样本数
  多 seed 方差

关键消融
  调度律形式（乘性 / 加性 / 老虎机）
  检测频率（每 N step，N 取总量 1/10 起步）
  指标平滑（EMA 窗口，防单次噪声带偏配比）
  ε_c 大小（回放配额 0% / 5% / 10% / 20%）
```

## 6 落到你们实验里的路线

```text
第 1 步  小规模验证：只用 T2 + T3（当前最弱的两类，失败率 39% / 37%）
         混训 vs 顺序 vs 调度，看 worst-case 指标与遗忘量
第 2 步  扩到 T1–T5，SFT 跑通；再在 GRPO 上复现
第 3 步  T6/T7 定稿后重跑调度器，展示"类目增加时自动再平衡"

节奏建议
  每训练 N step（≈总量的 1/10）评一次验证集
  权重更新加 EMA 平滑
  回放配额先设 5%–10%，已掌握类不低于这个值

工程落点
  数据侧每类任务池已带 T1–T5 标签，调度器只需输出
  采样权重表（json），训练脚本按权重采样
```

## 7 结论（三个问答）

```text
问 1  这套东西应该叫什么？
答    不要单叫"动态训练"。正统伞名是"课程学习 / 自适应数据调度"，
      完整定语 = 指标闭环 + 防遗忘回放 + 多任务 agentic post-training。
      建议名：Metric-Driven Adaptive Multi-Task Curriculum with Rehearsal
              （或 Performance-Aware Dynamic Data Scheduling, PADS）

问 2  能不能当论文的小创新点？
答    能，但要放准位置：作为"方法章节的一个小节 / 训练组件"，
      主贡献仍是任务体系与数据管线。三个前提：
      ① 把调度形式化成"worst-case + 遗忘约束"的在线优化（第 4 节）
      ② 与 ADS / DISCO / AdaCuRL 划清边界（第 3 节）
      ③ worst-case 指标与遗忘量对照齐全（第 5 节）

问 3  最大风险是什么？
答    ADS（2606.22305）已经非常接近，写之前先精读它；
      把"按类别指标闭环 + 回放约束"两处差异写实、写进动机。
```
