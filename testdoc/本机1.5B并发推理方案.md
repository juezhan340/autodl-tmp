# 本机 1.5B 并发推理方案

> 日期：2026-09-29
> 范围：只谈本机部署 1.5B 推理，不谈 SFT / GRPO。
> 机器以本次 `nvidia-smi` 为准，06 文档里的 4090 和后来误记的 5090 都作废。
> 数字由 `testdoc/kv_budget.py` 算出，KV 公式已核对；引擎开销尚未上机实测。

## 0. 本机与负载

```text
GPU     NVIDIA GeForce RTX 3080 Ti
显存    12288 MiB
架构    Ampere sm_86
驱动    595.71.05 / CUDA 13.2（用户态 torch 2.8.0+cu128）
CPU     2× Xeon Silver 4214R，48 线程
内存    440 GiB
磁盘    /root/autodl-tmp  130G 几乎空

模型    Qwen2.5-1.5B-Instruct
        hidden=1536  layers=28  heads=12  kv_heads=2  head_dim=128
        max_position_embeddings=32768
        BF16 权重约 2.95–3.0 GB

负载    HomeFlow 的 A：每轮一个工具 JSON
        实测末轮提示词 3.4k–7.8k 字符，约 2k–4k tokens
        生成不足 200 tokens
        单局最多 10 轮，前缀（system + 工具表）每轮几乎不变
```

1.5B 在这张卡上，显存瓶颈在 KV 池怎么分给「几路同时、每路多长」，不在权重。权重只占约 3GB。

## 1. 方案

并发推理用 vLLM 起 OpenAI 兼容口，BF16，不开量化。llama.cpp 只留作单路对照或以后往更小设备搬 GGUF，不作为本机并发方案。

```text
本机推理栈

  进程        vllm serve Qwen/Qwen2.5-1.5B-Instruct
  精度        BF16（3080 Ti 没有 Ada 的 FP8 张量核，不要套 5090 菜谱）
  接口        http://127.0.0.1:8000/v1
  客户端      现有 DeepSeek 那种 OpenAI Chat Completions 即可改 base_url

  评测默认档（独占卡）
    --gpu-memory-utilization 0.85
    --max-model-len 8192
    --max-num-seqs 16
    --enable-prefix-caching

  五路 HomeFlow 评测
    每路 8K 上下文，同时顶满约 1.2 GB KV
    12GB 卡上是轻松档，不是极限档
```

Qwen 官方部署文档推荐 vLLM。它按页分配 KV，多路共用一个池，这才是「支持并发」的含义。llama.cpp 单路解码可以和 vLLM 接近，一路以上就会串行，五路评测时墙钟会被拉长。

## 2. KV 怎么算

Qwen2.5-1.5B 是 GQA，每层只有 2 组 KV。BF16 下每个 token 的 KV 是：

```text
28 层 × 2(K,V) × 2 个 KV 头 × 128 维 × 2 字节
= 28672 bytes
≈ 28 KiB / token
```

vLLM 启动时按 `--gpu-memory-utilization` 预占显存，先放权重和引擎工作区，剩下的全切成 KV 页。多路并发抢的是这个池的总 token 数，不是「每路再复制一份权重」。

```text
KV 池 tokens ≈ (util × 12GB − 权重 3GB − 引擎开销) / 28 KiB

单路上限 = min(32768, 池 tokens / 并发路数)
           32768 是模型位置编码上限，再大也伸不过去
```

引擎开销（CUDA Graph、激活、临时缓冲）没有上机实测，下面三档用 1.2 / 1.0 / 0.8 GB 估。池子算小了只会让表更保守。

## 3. 并发 × 上下文

下面三张表都假设：**所有并发路同时顶满 max_model_len**。真实 HomeFlow 远到不了顶满，所以能打 OK 的格子，上机后还会更宽。

### 3.1 独占卡  util=0.85

vLLM 预占 10.20 GB，KV 池约 6.00 GB，合计约 22.5 万 tokens。

```text
并发     每路上限（被 32768 截断）
  1      32768          模型上限，不是显存上限
  4      32768
  5      32768          五路仍可同时开满 32K
  8      28086          八路同时满 32K 会超，满 16K 可以
 16      14043
 32       7021

同时顶满：
并发\上下文     4K     8K     16K    32K
  1            OK     OK     OK     OK
  4            OK     OK     OK     OK
  5            OK     OK     OK     OK
  8            OK     OK     OK     超
 16            OK     OK     超     超
 32            OK     超     超     超
```

这是本机独占卡跑 1.5B 的主表。五路并发时，上下文长度的硬顶是模型自己的 32768，不是 12GB 显存。

### 3.2 留余量  util=0.70

KV 池约 4.40 GB，16.5 万 tokens。五路 32K 仍 OK。八路只能收到约 20K。给驱动、日志、偶发峰值留一点。

### 3.3 和别的进程分卡  util=0.45

KV 池只剩约 1.60 GB，6.0 万 tokens。

```text
并发     每路上限
  1      32768
  4      14979
  5      11983          五路请把 max_model_len 收到 8K
  8       7489          八路 8K 会超，改 4K 或降并发
 16       3744
```

只有这档才会让「五路并发」和「长上下文」打架。训练进程或另一个模型占着卡时，走这一档，并把 `--max-model-len` 写成 8192。

## 4. 落到 HomeFlow

从 `runs/x5_20260929` 把 A 的提示词按真实模板填回去，末轮长度如下。中英混排按 2 字符/token 估，偏大不偏小。

```text
最长一条   T2 sc_005  10 轮   7784 字符   ≈ 3900 tokens
T5 观察类  7 轮               ≈ 3300 tokens
多数 T1/T4 4–6 轮             ≈ 2200 tokens
生成       一个工具 JSON      < 200 tokens
```

即便把历史原样塞进 prompt，十轮结束也到不了 8K。工具表每轮重复，打开 prefix caching 之后，后几轮的预填充会更短。

```text
HomeFlow 评测五路
  实际每路峰值     ≈ 4K
  建议 max_len     8192          留一倍余量
  五路同时顶满 8K  ≈ 5 × 8192 × 28KiB ≈ 1.17 GB KV
  独占卡 6 GB 池   还剩大半给突发和对齐

所以：
  支持并发：可以，vLLM 五路、八路都在舒适区
  并发时的上下文：评测写 8192；独占卡理论上五路仍可 32768
```

以后如果把八个工具的完整 JSON schema、更长房间状态、或 20 轮历史都拼进 prompt，再把 `--max-model-len` 升到 16384。独占卡上五路 16K 仍然 OK。

## 5. 启动规格

```text
模块名    本机 1.5B 推理服务

职责：    给 A / 评测客户端提供 OpenAI 兼容的 chat.completions
输入：    messages、可选 tools、采样参数
输出：    助手文本或 tool_calls
读取：    HF 或本地的 Qwen2.5-1.5B-Instruct 权重
写入：    不写训练产物；日志打到 stdout
不负责：  SFT、GRPO、改 HomeEnv、量化导出 GGUF

对应命令（独占卡、五路评测）：

  vllm serve Qwen/Qwen2.5-1.5B-Instruct \
    --host 127.0.0.1 \
    --port 8000 \
    --dtype bfloat16 \
    --gpu-memory-utilization 0.85 \
    --max-model-len 8192 \
    --max-num-seqs 16 \
    --enable-prefix-caching

分卡时把 util 改 0.45，max-num-seqs 改 8，max-model-len 仍 8192。
```

请求里自己带 `temperature / top_p / repetition_penalty`。vLLM 服务端默认采样对 Qwen2.5 偏容易重复，官方文档要求调用方覆盖。权重放到 `/root/autodl-tmp`，不要放系统盘。

安装注意：当前环境没有 vLLM，torch 是 `2.8.0+cu128`。装的时候要一张带 Ampere sm_86 的轮子，不要下成 Blackwell 专用包。装好后看启动日志里的 `GPU KV cache size`，用它替换第 3 节的估算池子。

## 6. 明确不采用

```text
llama.cpp / Ollama
  单路可以，五路评测会串行
  GGUF 和即将用来评测的 HF 权重要转一遍
  工具 JSON 的 chat template 要自己对齐

TensorRT-LLM、FP8、NVFP4
  3080 Ti 不是 Ada/Hopper/Blackwell
  1.5B 的 3GB 权重不值得为这一点去编译

默认 util=0.90 且 max-model-len=32768
  服务能起来，但会看起来像「1.5B 吃满一张卡」
  评测不需要 32K，把长度和预占都写死更干净
```
